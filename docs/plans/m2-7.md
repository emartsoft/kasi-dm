## 2. Design

### 2.1 Layout

```text
docs/store/
├── listing/en-US.md                 short and long description, single purpose, category, what a reviewer should try
├── permission-justifications.md     one paragraph per permission and for the content script, each naming the code that uses it
├── data-usage.md                    the per-store data disclosure answers
├── review-notes.md                  how to test without the desktop app: what "not connected" means, how to see the popup
└── screenshots/                     1280x800 screenshots, generated by the e2e harness (optional step)
docs/legal/privacy-policy.md         the policy the listings link to
extension/scripts/package.ts         builds, checks and zips
```

Icons come from `extension/public/icons`. Promo tiles (440x280, 1400x560) are the owner's design (section 5).

### 2.2 Justifications that match the code

| Permission | Why (and the code that uses it) |
| --- | --- |
| `downloads` | Pause a matching download while Kasi takes it, then cancel, remove and erase the browser's copy (`shared/interception.ts`). |
| `cookies` | Read the cookies the browser would send for that download so Kasi can fetch with the same login (`shared/cookies.ts`); read only after a match and sent only to the local app. |
| `webRequest` (non-blocking) | Remember which main-frame and sub-frame requests were not GET, so form-POST downloads are left to the browser (`shared/request-tracker.ts`). It never reads or changes headers or bodies. |
| `nativeMessaging` | Talk to the Kasi desktop app through its registered host (`shared/native-port.ts`). |
| `storage` | Cache the rules Kasi pushed, the interception toggle, and short-lived hashes for the bypass key and POST marks (`shared/rules-cache.ts`, `request-tracker.ts`, `bypass.ts`). |
| `contextMenus` | The "Download with Kasi" menu items (M2.5b). |
| `scripting` | Collect page links for "Download all links" on the user's request (M2.5b). |
| `<all_urls>` host permission and the content script | Read cookies for, and observe requests on, any site a download may come from; the content script only reports whether Alt, Ctrl or Shift was held on a trusted click, and answers a link-collection request from this extension. It sends nothing to the page or to any server. |

`docs/store/permission-justifications.md` is generated from this table and a unit test fails when the manifest's permissions differ from the table (a new permission cannot ship without a justification).

### 2.3 The packager (`npm run package`)

1. `npm run build` (both targets, `check-manifests`).
2. Refuses to continue if a manifest contains `key`, `update_url`, a localhost match, or source maps are present in `dist`.
3. `web-ext build` for `dist/chromium` and `dist/firefox` into `dist/packages/kasi-extension-<target>-<version>.zip`, with the version read from the manifest.
4. `git archive` of `extension/` plus `docs/store/amo-build.md` (Node version from `.nvmrc`, `npm ci`, `npm run build:firefox`) into `kasi-extension-source-<version>.zip` for AMO.
5. Unit test over the zips: only distribution files, the manifest version equals `package.json`, no `tests/`, no `.map`.

## 3. Verification

- Package tests of 2.3 step 5; the justification-table test of 2.2; `web-ext lint --warnings-as-errors` on `dist/firefox` (exists); a Chromium manifest check for the store's own rules (MV3, icon sizes, no prohibited keys) in `check-manifests`.
- **Mutation checks, each must fail a named test:** a `key` in a package; a `.map` in a package; a permission added with no justification; a zip with the wrong version.
- `npm run lint`, `format:check`, `check:types`, `npm test`, `npm run build`, `npm run package`.

## 6. Decisions (approved: the recommended option, the first of each, was chosen for all)

**Owner actions** are in section 5 (accounts, policy URL, promo tiles, the submissions).


1. **When and how to submit.** After M2.8b, as **unlisted** (Chrome, Edge) and **unlisted on AMO**, with `review-notes.md` explaining that the companion app is in development (**recommended**: real review feedback before the alpha, no public users of an unfinished app). **Or** submit publicly now (reviewers and users see "not connected"; a rejection for non-working functionality is likely). **Or** wait for the M4 installer (no early feedback, which defeats the risk mitigation).
2. **Zipping.** `web-ext build` for both targets (**recommended**, no new dependency). **Or** `archiver`/`jszip` (MIT, a new dev dependency) for full control over the file list.
3. **AMO source.** `git archive` of `extension/` with build instructions (**recommended**). **Or** point AMO at the public repository tag (needs the repository public by then).
4. **Listing languages.** English only (**recommended**). **Or** add Swahili now (a translation to maintain before the product has users).
5. **Screenshots.** Generate the 1280x800 popup and options screenshots from the e2e harness (**recommended**; they stay current). **Or** take them by hand per release.
6. **Privacy policy host.** The repository page until a martsoft page exists (**recommended**). **Or** wait for the website (blocks the submission).
