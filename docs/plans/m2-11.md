  - **11d: Mark-of-the-Web** (`CAT-003`; `TC-CAT-003`): the engine writes the `Zone.Identifier` stream when a download completes.
  - **11e: optional scan** (`CAT-004`; `TC-CAT-004`): a setting, off by default, that scans the finished file through AMSI.

## 2. Decisions

1. **Rules live in one table.** `category_rule (id, category_id, kind, pattern, position, is_builtin)`, `kind` in `extension | domain | url`. Built-in categories get their extension rules from migration seed rows (the TRD 10.4 table, plus the extra extensions in question 8). Torrent jobs go to Torrents by job kind, not by a rule. The migration takes the next free number at PR time (M3's 3c also adds one; whoever merges second renumbers, as the M3 plan says).
2. **A pure resolver.** `CategoryResolver.Resolve(link, fileName, mime, kind, rules, categories)` has no I/O and no clock, so the order is testable by tables. It follows TRD 10.4 exactly:
   1. user rules by domain or URL, in `position` order, first match wins;
   2. extension rules, user rules before built-in ones, then by position;
   3. the MIME type, only when the file name has no extension;
   4. General.
3. **Patterns are globs**, `*` and `?`, case-insensitive. A **domain** rule is matched against the host. A **URL** rule is matched against the address without its query and fragment (a query can carry a token, and a rule should not depend on one). An **extension** rule is the text after the last dot, and a double extension such as `tar.gz` is tried first. A pattern that is empty, or only `*`, is refused when saved.
4. **Folders** stay relative to the user's Downloads folder, as today (`category.folder`, empty for General). A folder with `..`, a rooted path or a reserved Windows name is refused unless question 3 is answered yes. The resolver returns a category; `JobService` turns it into a folder.
5. **Precedence of the choices a user makes** (question 1): what the user picks in the dialog, then the remembered choice for the site, then the rules, then General. The rules therefore never override a person.
6. **Applying (11b).** `JobService.AddAsync` resolves when the request names no category, so the browser hand-off, the picker and the clipboard are covered in one place. The Add dialog re-resolves as the link or the file name changes, until the user touches the category or folder box by hand. A MIME type the browser sent (`addDownload.mime`) feeds the resolver. For a typed link with no extension and no MIME, the probe may know better (question 7): the recommended behaviour is one re-resolve right after the probe, only for a job that was categorised by the fallback and has written no bytes.
7. **Mark-of-the-Web (11d).** After `SealAsync` and before `CommitAsync`, the engine writes `Zone.Identifier` on the part file (the stream travels with the rename) with `ZoneId=3`, and, if question 4 is answered that way, `HostUrl` with the address **without query or fragment**. It is written for every completed file of every kind. There is no switch (question 5): this is a safety property like the DRM refusal, and the TRD lists it as P1. A volume that has no streams (FAT32, exFAT, some shares) is not an error: the job completes and the job log gets one fixed line ("Mark-of-the-Web not supported on this volume"), because a download must not fail for a safety mark the volume cannot hold.
8. **The scan (11e).** `IFileScanner` in `Kasi.Core` with an AMSI implementation in `Kasi.Engine` (P/Invoke `AmsiInitialize`, `AmsiOpenSession`, `AmsiScanBuffer`, `AmsiCloseSession`). It runs after the seal and before the rename, only when the setting is on, and only on Windows with AMSI present. The mechanism and the limits are question 6. A scan that cannot run (AMSI missing, provider error) never fails the download: the log says it was not scanned.
9. **No sensitive data in logs.** Rule matching logs nothing. The job log lines for the safety steps are fixed words: no address, no path, no rule pattern (CLAUDE.md rule 3).
10. **UI (11c).** A Categories tab in Settings: a list of categories (name, folder, built-in marked), a grid of rules for the chosen category (kind, pattern, order with move up and down), add, edit and delete (a built-in category can have its folder changed and its rules disabled, but is not deleted), and a "try a link" box that shows which category and folder a link would get and **which rule matched**. All text in resource files, automation names on every control, keyboard-operable (CONTRIBUTING.md section 6).

## 3. Tests per PR

- **11a:** `CategoryResolverTests` (`TC-CAT-001`): every default extension lands in its category; `tar.gz`; upper-case extensions; no extension plus a MIME; unknown goes to General. `TC-CAT-002`: `*.example.com` beats the extension rule; two user rules, order decides; a URL rule ignores the query; an invalid pattern is refused. `CategoryRuleRepositoryTests` on a real SQLite file (create, order, delete, the seed rows present). Mutation checks: swap the order of rule kinds; ignore `position`.
- **11b:** `JobService` integration test (`TC-CAT-001`): a `.mp4` from `Kasi.TestServer` completes in the Video folder; a rule `127.0.0.1` sends a file to a custom category (`TC-CAT-002`); the dialog's choice and the remembered site still win. `AddDownloadViewModel` tests for re-resolving while typing and for stopping once the user chooses. A headless test that the browser hand-off path uses the resolver. Mutation check: bypass the resolver in `AddAsync`.
- **11c:** view-model tests for the tab (add, edit, move, delete, refusals, the "try a link" result), a headless window test for automation names and keyboard use, and one FlaUI flow (add a rule, add a download, see it in the right folder) in `Kasi.App.UiTests`.
- **11d:** `TC-CAT-003` on a real NTFS temp folder: after a download completes, `file:Zone.Identifier` exists and reads `ZoneId=3`; the stream is still there after the rename; a volume without streams completes with the log line; a resumed download gets the mark once. Mutation check: write the stream to the wrong file.
- **11e:** `FileScannerTests` with a fake scanner (a detection ends the job as specified in question 6; "could not scan" never fails it; off by default writes no call). `TC-CAT-004`: the real AMSI wrapper is called with the **EICAR string built in memory at run time** (never saved as a file in the repository, so no antivirus quarantines the checkout) and must report detection; the test is skipped with a printed reason when AMSI is not available or no provider answers. A second test runs the whole completion step with the fake scanner returning "detected".

## 5. Risks

| Risk | Handling |
| --- | --- |
| Antivirus on a developer machine or a CI runner quarantines the EICAR test | the string exists only in memory, assembled from parts at run time; the real-AMSI test skips itself with a reason if no provider answers |
| A rule sends files outside Downloads | folders are relative and validated (decision 4) unless the owner allows more |
| A pattern is slow or hostile | globs are matched without backtracking (a linear matcher, not `Regex`); a pattern is capped at 256 characters |
| The category chosen at creation is wrong once the probe knows the MIME | decision 6, one bounded re-resolve before any bytes are written |
| The mark makes a user's own files look untrusted | it is the Windows convention for anything from the internet, which is its purpose; the TRD asks for it |
| Resume or restart writes the mark twice, or on a half file | it is written only at the completion step, once |

## 6. Out of scope

Categories for torrents beyond the fixed Torrents routing (M4), importing rules from another manager, and per-category speed limits or queues (not in the TRD).

## 7. Questions for the owner (all answered 2026-10-24: every recommendation accepted)

1. **Precedence.** Do the rules come after the dialog choice and the remembered site, as decision 5 says? (Recommended: yes; the rules never override a person.)
2. **`*.github.com`.** Does it match `github.com` itself? (Recommended: no; a person who wants both writes two rules, and the "try a link" box shows what matched.)
3. **Folders outside Downloads.** May a user category use an absolute folder such as `D:\Media`? (Recommended: yes for user categories, with the usual path validation; built-in categories stay relative.)
4. **Mark-of-the-Web content.** `ZoneId=3` only, or also `HostUrl` with the query and fragment removed? (Recommended: also `HostUrl`, so SmartScreen has the origin; the query is never written.)
5. **A switch for the mark.** None, as in decision 7? (Recommended: none.)
6. **The scan.** (a) Mechanism: `AmsiScanBuffer` over the file in windows (recommended: 4 MiB windows overlapping by 64 KiB, files up to 512 MiB; larger files are left to Windows' own on-access scanning and the log says so), or the Defender command line, which is Defender-only. (b) On a detection: fail the job with a fixed "flagged by antivirus" message and **leave the file where the antivirus put it**, or delete it ourselves? (Recommended: fail the job, never delete; Kasi does not remove what the antivirus has already handled, and "never lose data" holds.)
7. **The probe's MIME.** Re-resolve once after the probe for jobs categorised by the fallback (decision 6)? (Recommended: yes, in 11b.)
8. **Extensions.** Use the TRD 10.4 table as written, plus `bz2`, `tar.gz` (double extension), `deb`, `rpm`, `apk`, `dmg`, `pkg` under Compressed or Programs, as the browser defaults already list them? (Recommended: yes: archives and installers to the two folders by what a user would expect: `bz2`, `tar.gz` Compressed; `deb`, `rpm`, `apk`, `dmg`, `pkg` Programs.)
9. **Migration number.** Take the next free number when 11a is written and renumber if M3's 3c merges first? (Recommended: yes.)
