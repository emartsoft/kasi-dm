## 1. Decisions

1. **Architecture isolation (`SolutionLayout.cs`):** `Kasi.Scheduling` references only `Kasi.Core`. To trigger engine jobs without breaking layering, `Kasi.Core` defines `IJobControl`:
   ```csharp
   public interface IJobControl
   {
       Task StartJobAsync(JobId id, CancellationToken cancellationToken = default);
       Task PauseJobAsync(JobId id, CancellationToken cancellationToken = default);
   }
   ```
   `DownloadEngine` in `Kasi.Engine` already matches this interface and implements it directly.
2. **Fractional indexing for job ordering (`KASI-QUE-002`, TRD 11.2):** `job.queue_pos` is `REAL`. Inserting between positions $A$ and $B$ assigns $(A + B) / 2.0$. Moving to top assigns $A / 2.0$ (or $A - 1.0$), and moving to bottom assigns $Z + 1.0$. If $|A - B| < 10^{-6}$, rebalance assigns $1000.0, 2000.0, \dots$. Moving or reordering is a single `UPDATE job SET queue_id = @qid, queue_pos = @pos WHERE id = @id;`.
3. **Database schema for schedules:** SQLite migration `0005_queue_schedule.sql` introduces table `queue_schedule`:
   ```sql
   CREATE TABLE queue_schedule (
       queue_id        INTEGER PRIMARY KEY REFERENCES queue(id) ON DELETE CASCADE,
       is_enabled      INTEGER NOT NULL DEFAULT 0,
       start_time      TEXT NOT NULL,              -- HH:mm:ss
       stop_time       TEXT,                       -- HH:mm:ss, NULL = until queue empty
       days_of_week    INTEGER NOT NULL DEFAULT 127 -- bitmask (1=Sun, 2=Mon, 4=Tue, 8=Wed, 16=Thu, 32=Fri, 64=Sat)
   );
   ```
4. **Post-completion actions & safe power execution (`KASI-QUE-004`):**
   Power actions show a 60-second cancellable countdown. `IPowerController` encapsulates system calls (`SetSuspendState`, `InitiateShutdown`); tests use `FakePowerController` and `FakeTimeProvider` so no test ever triggers real OS power events. Actions are skipped if other queues are busy unless `ForceIfOtherQueuesBusy` is set.
5. **Missed schedules (`KASI-QUE-003`, `TC-QUE-007`):**
   If Kasi starts within an active schedule window (including overnight windows crossing midnight), the queue starts immediately. If the window has already passed, it waits for the next scheduled occurrence.

## 2. Deliverables breakdown

### 10a: Queue Runner & Ordering
- `IJobControl` defined in `Kasi.Core`.
- Migration `0005_queue_schedule.sql` in `Kasi.Data`.
- `IJobRepository.UpdateQueuePositionAsync` added to `Kasi.Core` and implemented in `Kasi.Data`.
- `IQueueRepository` extended with `AddAsync`, `UpdateAsync`, `DeleteAsync`.
- `QueueRunner` in `Kasi.Scheduling`:
  - Tracks running slots per queue against `queue.MaxParallel`.
  - Dispatches `StartJobAsync` when slots are open.
  - On job completion/pause/cancellation, refills slots from next `JobState.Queued` in order of `queue_pos`.
  - On permanent failure, shifts job to the tail of the queue (`max(queue_pos) + 1.0`) so bad links do not block the queue.
  - Reorder and move methods with fractional indexing.
- Test project `tests/Kasi.Scheduling.Tests` created and added to `Kasi.slnx`:
  - `TC-QUE-001`: Queue limit 2 never exceeded across 10 jobs.
  - `TC-QUE-002`: Reorder and move between queues; order persists across restart.

### 10b: Scheduler & Missed Schedules
- `ScheduleEvaluator` and `QueueScheduler`:
  - Computes active state for same-day and overnight (crossing midnight) time windows.
  - Computes `NextStart` and `NextStop` timestamps based on `DayOfWeekMask`.
  - Hooks `TimeProvider` periodic timer to trigger queue start and stop.
  - Missed schedule detection on startup.
- Tests in `tests/Kasi.Scheduling.Tests`:
  - `TC-QUE-003`: Schedule 23:00–06:00 starts and stops within 1 minute (clock injected).
  - `TC-QUE-007`: Missed schedule within window starts at once; outside window waits.

### 10c: Post-Completion Actions
- `PostActionCoordinator`:
  - Triggers when all jobs in a queue reach terminal state (`Completed`, `Failed`).
  - Evaluates action kind: None, Sleep, Hibernate, Shutdown, ExitKasi, RunProgram.
  - Checks if other queues are running; skips power actions if busy and not forced.
  - Runs 60-second cancellable countdown timer via `TimeProvider`.
  - Invokes `IPowerController` or program runner on countdown expiry.
- Tests in `tests/Kasi.Scheduling.Tests`:
  - `TC-QUE-004`: Each post-action tested, including 60 s countdown completion and cancellation.

### 10d: App Integration & Scheduler Window
- Wire `QueueRunner` and `QueueScheduler` into `Kasi.App` startup and `DownloadEngine` lifecycle.
- Enable and wire toolbar buttons in `MainWindowViewModel`: "Start queue", "Stop queue", "Scheduler".
- Implement Scheduler window (queue configuration, schedule hours, days of week, post-action settings).
