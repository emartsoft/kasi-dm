## 2. Proposed Design & Public API (`src/Kasi.Engine/`)

All public types live in the flat `Kasi.Engine` namespace, as the existing code does **[changed]**. Win32 interop is internal, in `src/Kasi.Engine/Interop/`, marked `[SupportedOSPlatform("windows")]` **[added]**. Any file path in an error or log message goes through `Redact.Path` (`KASI-NFR-013`).

### 2.1 Result & Error Types (`src/Kasi.Engine/DiskOutcome.cs`)

Expected disk conditions are returned as values, not exceptions (CONTRIBUTING 3.1), using the same outcome pattern as `ProbeOutcome` instead of `out` parameters **[changed]**.

- **`DiskErrorKind`** (`enum`):
  - `NotEnoughSpace` — the pre-start check failed, or the OS reported disk full (`0x80070070`, `0x80070027`) or a disk-quota error on write, `SetLength` or flush. Maps to `JobState.Paused` with a "not enough space" reason (ADR 0002) in the caller.
  - `PartFileMismatch` — on resume, `.kasipart` is missing or its length does not match `TotalBytes`.
  - `LengthMismatch` — at seal, the actual length differs from the expected length (external truncation or extension; see 2.3 for what this does *not* catch).
  - `IncompleteData` **[added]** — at seal, the caller-supplied written-byte total or the allocated-range check shows the file is not fully written.
  - `TargetExists` **[added]** — at commit, the final name is taken and overwriting was not requested.
  - `IoError` — any other `IOException` / `UnauthorizedAccessException` (device removed, access denied, part file in use by another job).
- **`DiskStatus`** (`readonly record struct`) **[changed]**: `bool IsSuccess`, `DiskErrorKind? ErrorKind`, `int? NativeErrorCode` and `string? Detail` (redacted, for logs only). It carries **no user-facing text**: the app maps `ErrorKind` to localised text from resource files (CONTRIBUTING 6).

### 2.2 Free-Space Check & `IDiskSpaceProvider` (`src/Kasi.Engine/IDiskSpaceProvider.cs`)

- **`IDiskSpaceProvider`**: `bool TryGetAvailableFreeBytes(string directoryPath, out long availableBytes)`
- **`WindowsDiskSpaceProvider`** (default): calls `GetDiskFreeSpaceExW` through `[LibraryImport("kernel32.dll", StringMarshalling = StringMarshalling.Utf16, SetLastError = true)]` on the target directory. Unlike `DriveInfo` on a drive root, this works for a VHD mounted on a folder, for UNC paths, and respects per-user quotas (`lpFreeBytesAvailableToCaller`).
- **Pre-start check** (inside `TryOpen`), when `totalBytes` is known (`> 0`):
  - New download: `availableBytes >= totalBytes`.
  - Resume with an existing `.kasipart`: `availableBytes >= max(0, totalBytes - alreadyWrittenBytes)`, because the sparse holes are not yet backed by clusters.
  - Otherwise return `NotEnoughSpace` before creating or modifying any file.
  - **[added]** Known limit: two jobs can both pass the check against the same free space. The mid-transfer `ERROR_DISK_FULL` handling is the backstop; queue-level space reservation is a later concern.

### 2.3 `PartFileWriter` (`src/Kasi.Engine/PartFileWriter.cs`)

Manages the single `<fileName>.kasipart` handle for one job (`IAsyncDisposable`, `IDisposable`). Disposing without sealing keeps the `.kasipart` (that is what pause and shutdown need).

- **Constants:** `PartExtension = ".kasipart"`, `WriteBufferSize = 256 * 1024`.
- **`TryOpen`** (static, returns an outcome that holds the writer or a `DiskStatus`) **[changed]**, with parameters `folderPath`, `fileName`, `totalBytes`, `resume`, `alreadyWrittenBytes`, optional `IDiskSpaceProvider`:
  1. Validates `fileName` as a bare name (no separators, not rooted, no `..`) and that `PartPath` and `FinalPath` stay inside `folderPath`. The name has already been through `FileNameSanitiser` (M1.3).
  2. Runs the pre-start free-space check (2.2).
  3. `resume == true`: requires `PartPath` to exist and, when `totalBytes` is known, to have exactly that length (else `PartFileMismatch`); opens it with `FileMode.Open, FileAccess.ReadWrite, FileShare.Read, FileOptions.Asynchronous`.
  4. `resume == false`: opens with `FileMode.Create` (restarting a stale part file is intended). `FileShare.Read` lets other tools inspect the file during `TC-ENG-014`; a second job opening the same part file gets a sharing violation, returned as `IoError` **[added]**. When `totalBytes > 0`: `FSCTL_SET_SPARSE` (a filesystem without sparse support, `ERROR_INVALID_FUNCTION`, continues with ordinary pre-allocation and `IsSparse = false`), then `RandomAccess.SetLength`. If `SetLength` fails with disk full, close and delete the empty part file and return `NotEnoughSpace`.
  5. `totalBytes == null` (chunked): no sparse flag, no `SetLength`, no free-space check; the file grows and the OS disk-full error is the only protection.
- **`WriteAsync(ReadOnlyMemory<byte> buffer, long offset, CancellationToken)`** → `ValueTask<DiskStatus>`: validates `offset >= 0` and, when known, `offset + length <= TotalBytes`; writes with `RandomAccess.WriteAsync(...).ConfigureAwait(false)`. Carries `[AsyncMethodBuilder(typeof(PoolingAsyncValueTaskMethodBuilder<>))]` **[added]** so an asynchronously completing write does not allocate a state-machine box. Disk-full and quota `IOException`s become `NotEnoughSpace`; never throws for those.
  - **[added] Failure contract:** when a call returns an error, **none** of its bytes count as written, even if the OS wrote part of the buffer. The caller must not call `AdvanceLease`; the range is simply written again later. Writes are idempotent, which also makes endgame duplicates (ADR 0004) safe.
  - Concurrent calls on one writer are allowed (`RandomAccess` on an async handle is safe for that).
- **`FlushAsync(CancellationToken)`** → `ValueTask<DiskStatus>`: `RandomAccess.FlushToDisk`, **[changed]** run through `Task.Run` because `FlushFileBuffers` blocks (hundreds of milliseconds on an HDD) and must not stall the caller. Errors become `DiskStatus`. Per ADR 0003/0004 the caller snapshots cursors, then flushes, then records.
- **[changed] Two-phase finalise**, replacing the single `FinaliseAsync`, so verification steps can slot in before the rename (TRD 6.4 order: verify, Mark-of-the-Web, rename):
  - **`SealAsync(long? expectedLength = null, long? bytesWritten = null, CancellationToken)`**: (1) flush; (2) compare `RandomAccess.GetLength` with `expectedLength ?? TotalBytes` → `LengthMismatch`; (3) **[added]** completeness: if `bytesWritten` is given it must equal the length → `IncompleteData`; and, if the spike (section 5, item 8) confirms it, `FSCTL_QUERY_ALLOCATED_RANGES` must return exactly `[0, length)`; (4) clear the sparse flag with `FSCTL_SET_SPARSE { SetSparse = 0 }`, treating `ERROR_INVALID_FUNCTION` / `ERROR_INVALID_PARAMETER` as non-fatal once the length checks passed. The handle stays open, so M1.12 can read the file to hash it and M2.11 can write the `Zone.Identifier` stream.
  - **`CommitAsync(bool overwriteDestination = false, CancellationToken)`** **[changed default]**: closes the handle, then `File.Move(PartPath, FinalPath, overwrite)`. An existing destination without `overwriteDestination` → `TargetExists` (the part file is kept); choosing a free name is the caller's policy.
  - **Why the length check alone is not enough [added]:** `SetLength(totalBytes)` happens at open, so the length is always right. A premature seal would still pass it and leave zero-filled holes. The engine must therefore seal only when `SegmentScheduler.IsComplete` and pass `bytesWritten = scheduler.TotalWritten`; the allocated-range check is a second, independent guard.
- **`Abandon()`** **[added]**: closes the handle and deletes the `.kasipart` (job cancelled or removed). `Dispose` never deletes.

### 2.4 `PooledPartWriteBuffer` (`src/Kasi.Engine/PooledPartWriteBuffer.cs`)

Per-worker coalescing buffer over `ArrayPool<byte>.Shared`:

- **[changed]** Rents a 256 KiB array when the worker's lease starts (first use) and returns it when the lease ends, is superseded, or the worker pauses, not for the worker's whole lifetime. With 20 jobs × up to 32 connections a permanent buffer would be 160 MiB against the 250 MB budget (`KASI-NFR-004`); only workers with an active lease hold one.
- Exposes `Memory<byte> AvailableWindow` for `Stream.ReadAsync` straight into the buffer. **[added]** The window is capped at the lease end, so a read never crosses `lease.End`.
- Tracks `_windowStartOffset` and `_bufferedBytes`. When the buffer is full (256 KiB), **[added]** when the oldest buffered byte is older than 500 ms (`TimeProvider`), or on lease completion / pause / error, it writes `_buffer.AsMemory(0, _bufferedBytes)` to `PartFileWriter.WriteAsync` at `_windowStartOffset`.
  - *Why the age limit:* the scheduler's speed samples, the 250 ms ramp-up windows and the 10 s slow-lane check are fed by `AdvanceLease`. At 50 KB/s a 256 KiB buffer would produce one sample every ~5 s, which blinds them. 500 ms is the default and a constructor option.
- Returns the byte count so the caller calls `SegmentScheduler.AdvanceLease(leaseId, flushedBytes)` **only after `WriteAsync` returned success** (ADR 0003/0004: `Written` only counts bytes already handed to the file). If `AdvanceLease` reports `IsSuperseded`, the remaining buffered bytes are dropped. On a write error nothing is advanced (see the failure contract above).

## 3. Verification (`tests/Kasi.Engine.Tests/`)

### 3.1 Unit & Local Filesystem Tests

1. **`TC-ENG-014` (sparse `.kasipart` lifecycle)** — `PartFileWriterTests`:
   - Open a `10 MiB` part file in a temp directory: `<name>.kasipart` exists, `<name>` does not, length is `10 MiB`, `FileAttributes.SparseFile` is set (NTFS).
   - Write out-of-order segments from 8 concurrent tasks through `PooledPartWriteBuffer` with `GeneratedContent` bytes. **[added]** Include overlapping duplicate writes of the same range (endgame) and check they are harmless.
   - `SealAsync` then `CommitAsync`: the part file is gone, `<name>` is `10 MiB`, the sparse flag is cleared, SHA-256 matches `GeneratedContent.Sha256Hex`.
2. **Coalescing and allocation** — `PooledPartWriteBufferTests`:
   - Feed 16 KiB chunks; `WriteAsync` runs only every 256 KiB, on the 500 ms age limit (fake `TimeProvider`), and for the final tail; the file matches SHA-256.
   - **[changed] Allocation test:** write 32 MiB in 16 KiB chunks after warm-up. Measure with `GC.GetTotalAllocatedBytes(precise: true)` in a non-parallel test collection (`GetAllocatedBytesForCurrentThread` would miss thread-pool continuations). Assert no growth per 16 KiB chunk and a small fixed bound per 256 KiB write, single-threaded and with 8 concurrent writers.
   - **[added]** A window never crosses the lease end; a superseded lease drops its buffer; the buffer returns to the pool when the lease ends.
3. **Free space and error classification:**
   - A stub provider reporting less than `TotalBytes` on a fresh open → `NotEnoughSpace`, no file created.
   - Resume with `TotalBytes = 100 MiB`, `alreadyWrittenBytes = 60 MiB`, `available = 50 MiB` → succeeds (only 40 MiB remains).
   - Injected `IOException`s with `HResult` `0x80070070` and `0x80070027` (and the quota code, **[added]**, confirmed by the spike) during write, `SetLength` and flush → `NotEnoughSpace`, never thrown.
   - **[added]** After a failed write, no bytes count: a test resumes, rewrites the range, and the file hashes correctly.
4. **Resume, seal and commit edge cases:**
   - Resume with a missing or wrong-length part file → `PartFileMismatch`.
   - Seal with a length different from `expectedLength` → `LengthMismatch`, part file kept.
   - **[added]** Seal of a file with an unwritten hole → `IncompleteData`, part file kept, nothing renamed (the case the old length check missed).
   - **[added]** Commit onto an existing destination → `TargetExists`, part file kept; with `overwriteDestination: true` it replaces.
   - Unknown length (`TotalBytes = null`) → grows as written, seals with `expectedLength = totalWritten`.
   - `0 B` file → empty part file, seals and commits to an empty file.
   - Detail strings redact directory paths via `Redact.Path`; **[added]** `DiskStatus` carries no user-facing text.
5. **[added] Flush while writing** (ADR 0003 contract): writers run continuously while the test takes a cursor snapshot, calls `FlushAsync`, then records. After a simulated reopen, every byte below each recorded cursor is on disk and correct.

### 3.2 Small VHD Integration Test (`PartFileVhdIntegrationTests`, `Category=Integration`, `TC-ENG-015`)

- Tagged `[Trait("Category", "Integration")]` and `[Trait("TC", "TC-ENG-015")]`; covers the **writer level** of `TC-ENG-015`.
- Creates and mounts a 64 MiB NTFS `.vhdx` on a temporary folder with `diskpart` (works without the Hyper-V module). GitHub's `windows-2025` runner is elevated, so it runs in CI. **[changed]** Locally, when not elevated or when mounting fails, it calls `Assert.Skip`. In CI, `KASI_REQUIRE_VHD=1` makes that situation a **failure** instead, so the test cannot skip silently forever. It runs on the x64 leg only unless `diskpart` is shown to work on the `windows-11-arm` leg.
  1. `TryOpen` a `20 MiB` download while enough space is free (the pre-start check passes); then write a ballast file sized so only about `10 MiB` plus filesystem slack remains. **[changed]** The sequential writer then fails in the 40–70% range, and the test asserts the failure offset lies in that range rather than at exactly 50%.
  2. Write 256 KiB chunks until the real `ERROR_DISK_FULL` comes back as `NotEnoughSpace`; check the previously flushed bytes are intact.
  3. Delete the ballast, reopen with `resume = true` from the last flushed offset, write the rest, `SealAsync` + `CommitAsync`, and check the SHA-256.
  4. Always detach the VHD and delete the `.vhdx` in `DisposeAsync`.
- **[added]** The remaining half of `TC-ENG-015` (the job pauses with "Not enough space" and resumes after space is freed) is recorded in `plan.md` against M1.7/M1.8 so the test case is not ticked off early.

## 5. Decisions & Questions to Confirm

Items 1–3 were open in the first draft and are settled by the review. Items 4–8 are new; I will use the stated defaults unless you say otherwise.

1. **Clearing the sparse flag on seal (TRD 6.4):** issue `FSCTL_SET_SPARSE { SetSparse = 0 }`, assert on NTFS that `FileAttributes.SparseFile` is cleared, and treat `ERROR_INVALID_FUNCTION` / `ERROR_INVALID_PARAMETER` as non-fatal once the length checks pass. The step-2 spike confirms the behaviour before the test relies on it.
2. **Pre-start vs mid-transfer disk full:** because the sparse `SetLength` allocates no clusters, a ballast written after `TryOpen` produces a genuine `ERROR_DISK_FULL` mid-transfer. The pre-start check is covered by unit tests; the mid-transfer failure by the VHD test, asserted in a 40–70% range.
3. **Skipping the VHD test locally:** yes, `Assert.Skip` when not elevated, but `KASI_REQUIRE_VHD=1` in CI turns a skip into a failure.
4. **Finalise is two-phase (`SealAsync` + `CommitAsync`)**, chosen over a single `FinaliseAsync` or a callback, so M1.12 (checksum) and M2.11 (Mark-of-the-Web) slot in without changing the writer.
5. **`overwriteDestination` defaults to `false`**, with a `TargetExists` outcome; picking a free file name belongs to the caller (categories and auto-rename, M2).
6. **Max-age flush of 500 ms** in the write buffer, so the scheduler's speed sampling keeps working at low speeds; configurable.
7. **`DiskStatus` carries no UI text;** the app maps `DiskErrorKind` to resource-file strings.
8. **Seal-time completeness check:** `bytesWritten` from the scheduler is mandatory in the engine's call. The `FSCTL_QUERY_ALLOCATED_RANGES` check is added only if the spike confirms that explicitly written zero runs stay allocated on a sparse NTFS file; otherwise the `bytesWritten` check stands alone and ADR 0005 records why.
