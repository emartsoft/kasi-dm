## 1. Scope

M1.10 completes the engine-side authentication, cookie scoping, DPAPI secret storage, redirect handling and signed-URL link refresh. The browser-extension hand-off and the "Refresh link" prompt come in M2.8 and M2.12.

- **Basic and Digest authentication (`KASI-ENG-009`, `TC-ENG-016`):** authenticate the probe and every lease against `Basic` and `Digest` challenges, and never send credentials to another origin.
- **Forwarded cookies and headers (`KASI-ENG-009`, `KASI-NFR-013`, `TC-ENG-016`):** attach a cookie only when its domain, path and `Secure` attribute match the request URI; never forward sensitive headers across origins; never log secret values.
- **DPAPI `job_secret` persistence (TRD 9.4, 11.1, 11.2, 13.1):** protect per-job cookies, headers and credentials with Windows DPAPI (`DataProtectionScope.CurrentUser`), load them on resume, delete them when the download completes.
- **Redirects (`KASI-ENG-010`, `TC-ENG-017`):** chains of 1, 5 and 10 hops (including cross-host) complete and every lease uses the final URL; 11 hops fails with a clear error. The 10-hop cap already exists in `HttpProber`; this task proves it end to end and makes each hop use the right origin.
- **Signed-URL expiry and link refresh (`KASI-ENG-010`, `TC-ENG-018`, TRD 6.6):** a `401`/`403` mid-transfer stops without retry and keeps the flushed bytes and checkpointed cursors; a refreshed URL is validated against the stored file identity before any byte is written, then the transfer continues from the saved bytes.

Out of scope: job state transitions after an auth failure and the "ask the extension for fresh cookies" step (engine facade, M1.13, and M2.8/M2.12), SHA-256 Digest, NTLM/Negotiate, proxy credentials (M1.12).

## 2. Design

### 2.1 Scoping rules (the contract the tests pin)

| Thing | Scope | Rule |
| --- | --- | --- |
| Cookie | **host**, path, `Secure` (RFC 6265; the port is ignored) | `Domain` with a leading dot matches the host and its subdomains on a label boundary; without a dot, or for an IP literal, it is host-only. Path: exact, prefix ending in `/`, or prefix followed by `/`. `Secure` cookies go to `https` only. |
| Credentials (`Basic`/`Digest`) | **origin** (scheme + host + port) of the initial request | Never sent to any other origin; an `https`→`http` hop therefore drops them. |
| Sensitive headers (`Authorization`, `Cookie`, `Proxy-Authorization`) | **origin** of the initial request | Dropped on any hop or lease whose origin differs, whichever source set them. |
| Other request headers (`User-Agent`, `Referer`, `Accept-Language`, …) | all hops | Sent as today. |

Header sources: `HttpTransferOptions.RequestHeaders` holds non-sensitive headers supplied by the caller; `JobSecret.Headers` holds the sensitive ones captured from the browser. If both set the same name, `JobSecret.Headers` wins. The sensitive-name rule applies to both sources, which closes the existing leak where `HttpProber` and the lease requests ([`HttpTransferRunner.cs:248`](../../src/Kasi.Engine/HttpTransferRunner.cs) for the prober, [`:849`](../../src/Kasi.Engine/HttpTransferRunner.cs) for leases) add `RequestHeaders` to every hop and to leases on a redirected host.

### 2.2 `Kasi.Core` — secret model and contracts (`src/Kasi.Core/`)

- **`JobCookie`** (`Name`, `Value`, `Domain`, `Path = "/"`, `Secure = false`, `HttpOnly = false`); JSON property names camelCase so the TRD 9.4 `addDownload`/`linkRefreshed` cookie array maps onto it unchanged (M2.12).
- **`HttpCredentials`** (`UserName`, `Password`).
- **`JobSecret`** (`IReadOnlyList<JobCookie> Cookies`, `IReadOnlyDictionary<string, string> Headers`, `HttpCredentials? Credentials`).
  - All three override `ToString()` to return `Redact.Placeholder` so interpolation never writes a cookie, header or password to a log (`KASI-NFR-013`, CLAUDE.md rule 3).
- **`IJobSecretRepository`:** `SetAsync(JobId, JobSecret, ct)` (upsert, on create and on link refresh; a missing job throws `InvalidOperationException`, not a raw foreign-key error), `GetAsync(JobId, ct)` (`JobSecret?`), `DeleteAsync(JobId, ct)` (`bool`).
- **`IJobRepository.UpdateUrlAsync(JobId id, string url, string? finalUrl, CancellationToken ct = default)` returns `Task<bool>`**, like `UpdateTransferMetadataAsync`: updates only `url` and `final_url`; `done_bytes`, validators, state and segment rows are untouched. It does not guard the job state (state edges are M1.13). Signed URLs carry tokens, so they are logged only through `Redact.Url`. Test fakes that implement `IJobRepository` (for example `BlockingJobs`) gain the method.

### 2.3 `Kasi.Data` — `JobSecretRepository` (`src/Kasi.Data/JobSecretRepository.cs`)

- Serialises `JobSecret` to UTF-8 JSON and protects it with `ProtectedData.Protect`/`Unprotect` (`CurrentUser`, no extra entropy: the TRD scope is "current-user DPAPI").
- `Kasi.Data` targets plain `net10.0` and warnings are errors, so the repository and its registration carry `[SupportedOSPlatform("windows")]` (CA1416). Tests that need real DPAPI call `Assert.SkipUnless(OperatingSystem.IsWindows(), …)`; CI is Windows-only today and the Ubuntu job planned for M1.12 will skip them.
- A corrupt, truncated or undecryptable payload throws `InvalidDataException` (ADR 0003 style).

### 2.4 `Kasi.TestServer` (`tests/Kasi.TestServer/`)

- **`/auth/digest/…`:** `401` with `WWW-Authenticate: Digest realm="kasi", nonce="<fixed per server>", qop="auth", algorithm=MD5`; validates the client's `Authorization` for `PathGates.BasicUser`/`BasicPassword`, accepts any `nc`, then unwraps the inner path. MD5 is mandated by the Digest scheme and used only here, so the CA5351 suppression carries that justification. SHA-256 Digest is not covered.
- **`/redirect-to?target=<absolute uri>`:** `302` to an arbitrary absolute URI, so a test can redirect from Host A to Host B.
- **`TestServerMetrics`:** add `BytesServed` and `RequestsServed` (the `Reset()` rules stay as they are), needed to prove that saved bytes are not fetched again.

### 2.5 `Kasi.Engine` — scoping, per-origin credentials, redirects, link refresh (`src/Kasi.Engine/`)

- **`JobCookieMatcher`:** implements the cookie rows of the table; `UseCookies` stays `false` so selection is explicit.
- **`RequestScope`** (one internal class, not an interface): holds the initial origin, the non-sensitive headers, the `JobSecret` headers and cookies; `Apply(HttpRequestMessage)` adds exactly what the request URI is entitled to. `HttpProber` calls it on every hop and the lease requests call it on every lease, so there is a single place that decides what leaves the machine.
- **Credentials in the pool:** `HttpHostPool` takes an optional `(Uri origin, NetworkCredential)` in its constructor (the pool is created per transfer, so the options type is unchanged). A lane whose origin equals the credential's origin gets `SocketsHttpHandler.Credentials` and `PreAuthenticate = true`; every other lane gets none. The handler answers both `Basic` and `Digest`; the extra `401` round trip per lane (and per lease for Digest) is expected and asserted, not hidden.
- **`HttpProber`:** gains a `Func<Uri, HttpMessageInvoker>` so each redirect hop uses its own origin's lane (the existing `HttpMessageInvoker` constructor stays) and a `RequestScope`.
- **Runner:** `HttpTransferOptions` gains `JobSecret? Secret` and `IJobSecretRepository? SecretRepository`. With `CheckpointJobId` set and `Secret` null, the runner loads the stored secret; after `TransferCompleted` it calls `DeleteAsync`.
- **Link refresh — `RefreshAndResumeAsync`** (same inputs as `ResumeAsync` plus the refreshed `Uri`):
  1. Probe the refreshed URL with the `RequestScope` (follows up to 10 hops, may use a newly supplied `JobSecret`).
  2. Compare the probe with the stored identity: `TotalBytes` must equal, and `ETag` (else `Last-Modified`) must equal. Any mismatch returns `TransferFailed { ErrorKind = FileChanged }` with the existing `SegmentsSnapshot` untouched and **no byte written**.
  3. On success persist the new `url` and `final_url` with `UpdateUrlAsync` (after validation, before the first lease), then run `ResumeAsync` against the probe's final URL; leases keep sending `If-Range`, so a `200` is still caught.
  4. The mid-transfer `401`/`403` half needs no new code: `TransferRetryPolicy` already classifies it as `AuthRequired` without a retry, workers stop, the part file is flushed and the cursors committed, and `TransferFailed` carries the snapshot.

## 3. Verification

**10a — secrets and persistence**
- `Kasi.Core.Tests` — `JobSecretRedactionTests`: `ToString()` on all three types never contains a secret value.
- `Kasi.Data.Tests` — `JobSecretRepositoryTests` (Windows-only skips): DPAPI round trip; raw SQLite blob inspection shows no plaintext secret; tampered blob throws `InvalidDataException`; `DeleteAsync`; cascade when the job row is deleted; `SetAsync` for a missing job throws `InvalidOperationException`; camelCase JSON matches the TRD cookie shape.
- `JobRepositoryTests` — `UpdateUrlAsync` changes `url` and `final_url` only (`done_bytes`, validators, state unchanged); returns `false` for an unknown job.

**10b — authentication, cookies and redirects (`TC-ENG-016`, `TC-ENG-017`)**
- `Kasi.TestServer.Tests` — Digest rejects anonymous and wrong-password requests with `401` + `WWW-Authenticate: Digest` and serves `206` with valid credentials; `/redirect-to` redirects.
- `JobCookieMatcherTests` (unit): exact vs `.domain` vs suffix lookalike `badexample.com`, IP literals, path prefix (`/dl` matches `/dl` and `/dl/file.bin`, not `/dl2/file.bin`), `Secure` on http vs https, port ignored.
- `RequestScopeTests` (unit): sensitive headers from either source are dropped for another origin and for an `https`→`http` hop; `JobSecret.Headers` wins on a clash; other headers still pass. **Regression test first:** with today's code a `RequestHeaders` `Authorization` reaches the redirect target, so it fails before the fix.
- `HttpTransferAuthAndRedirectTests` (integration, `TC-ENG-016`): 8-connection downloads from `/auth/basic/…`, `/auth/digest/…` and `/auth/cookie/…` match `GeneratedContent.Sha256Hex`; missing or wrong credentials fail with `401` (`AuthRequired`) and the server sees no retry loop (request count from the metrics); Digest/Basic request counts show the expected extra `401` per lane; secret stored by DPAPI, loaded by the transfer, deleted on `TransferCompleted`.
- Cross-host test (`TC-ENG-016`): Host A is `127.0.0.1:portA`, Host B is `localhost:portB` — two different host names, because cookie scope ignores ports. Host A receives its cookie and `Authorization` on hop 0; Host B receives neither after the `302`.
- `TC-ENG-017`: `DownloadAsync` over `/redirect/1|5|10/files/…` with 8 connections matches SHA-256, and every lease goes to the unwrapped `FinalUrl`; `/redirect/11/…` fails with `TooManyRedirects`.
- NFR-013 beyond `ToString`: for a failing 401, a bad redirect and a too-many-redirects run, `TransferFailed.Detail` and the probe text contain no cookie value, password or signed-URL query.

**10c — link refresh (`TC-ENG-018`)**
- `HttpTransferLinkRefreshTests` (integration): 32 MiB from `/signed/files/sg/33554432?exp=<t0>`, throttled with `ThrottleBytesPerSecond` so the transfer outlives the flip, SQLite checkpointing on. The server gets its **own** `FakeTimeProvider`; the runner keeps a separate clock, so advancing the server clock does not fire checkpoint ticks, the stall guard or backoff. When polling the segment repository shows at least 25% saved, advance the server clock past `t0`.
  - The next lease gets `403`; the transfer stops with `AuthRequired`, no retry, the part file is kept and the saved cursors are in SQLite (more than 0, less than the total).
  - `RefreshAndResumeAsync` with `exp=<t1>` (and a second case through `/redirect/2/signed/…`) completes with the SHA-256 of `GeneratedContent("sg", 33554432)`; the server `BytesServed` counted after the refresh is at most `total − saved` plus the 2 MiB endgame allowance, so saved bytes were not fetched again; `url`/`final_url` in SQLite are the new ones.
- A refreshed URL that serves a different length, and one that serves a different ETag, each return `FileChanged`, write nothing to the part file and leave the stored URL and cursors unchanged.
- Build, full tests and `dotnet format --verify-no-changes` for each PR.
