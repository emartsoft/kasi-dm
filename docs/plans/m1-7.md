## 2. Proposed Design & Public API

### 2.1 Step 2 (M1.7a) — Extend `Kasi.TestServer` with TLS, HTTP/2, Certificate Modes & Metrics (`tests/Kasi.TestServer/`)

ADR 0001 notes: *"HTTP/2 and TLS are not served yet; add them (with a generated certificate) when the first HTTP/2 test case needs them."*

1. **`TestServerOptions`, `TestServerTlsMode`, `TestServerProtocolMode`:**
   - `TestServerTlsMode`: `None` (default, plaintext on `127.0.0.1:0`; existing `TestServerHost.StartAsync()` stays backwards-compatible); `Valid` (ephemeral Root CA `CN=Kasi Test Root CA` plus a leaf signed by it, SAN `DNS:localhost` and `IP:127.0.0.1`, valid `[now - 5m, now + 1d]`); `Expired` (signed by the root, valid `[now - 2d, now - 1d]`); `SelfSigned` (self-signed leaf, not signed by `RootCertificate`); `WrongHost` (signed by the root, SAN only `DNS:wrong.example.test`). Leaves carry the `serverAuth` EKU and the root has CA basic constraints.
   - *Windows SChannel key-storage note:* in-memory certificates from `CertificateRequest` are exported to PKCS#12 and reloaded with `X509CertificateLoader.LoadPkcs12(pfxBytes, password: null, X509KeyStorageFlags.Exportable)` so SChannel can use the private key during Kestrel's handshake.
   - `TestServerProtocolMode`: `Http1` (default for plaintext), `Http2`, `Http1AndHttp2` (default when `TlsMode != None`).
   - **[changed]** `Http2MaxStreamsPerConnection` is dropped: worker lanes (2.2) make it unnecessary.
2. **Server metrics (`TestServerMetrics.cs`, built on the existing connection middleware in `ConnectionTracker`):**
   - On `TestServerHost`: `X509Certificate2? RootCertificate` (null when `TlsMode == None`, disposed with the host); `TotalConnectionsAccepted`; `PeakConcurrentConnections`; `TlsHandshakesCompleted`; `AbortedRequests`; `ResetMetrics()`.
   - **[changed] `TlsHandshakesCompleted` is counted after the handshake**, in connection middleware placed after `UseHttps`, using `ITlsHandshakeFeature`. `HttpsConnectionAdapterOptions.OnAuthenticate` is not used: it runs before authentication, so failed handshakes (the Expired, SelfSigned and WrongHost runs) would be counted as completed.
   - **[added]** `Http2RequestsServed` and `Http1RequestsServed`, counted from `Request.Protocol` in middleware, so `TC-ENG-002` can prove the transfer really used HTTP/2.
   - `AbortedRequests` is incremented when a request ends with `RequestAborted` set and `ChaosSession.Aborted` is not set.
3. **[added] Chaos extension for the live slow-lane test:** `ChaosProfile.OtherConnectionsBytesPerSecond` throttles every connection **except** `ThrottleConnectionIndex`, so one scenario can run connection 0 at 50 KB/s and the others at a steady, moderate rate. Without it the unthrottled connections finish a file in under a second and the 10 s slow-lane rule can never be reached (2.4, tests 3).
4. **Why per-connection throttling (`ThrottleConnectionIndex = 0`) works with `HttpProber`:** `ConnectionTracker` gives `Index = 0` to the first accepted connection. The probe uses lane 0 and worker 0 continues on that same connection, so worker 0 is throttled from byte 0 while the other lanes are not (`TC-ENG-008`).

### 2.2 Step 3 (M1.7a) — `HttpHostPool` & TLS Validation (`src/Kasi.Engine/HttpHostPool.cs`)

Manages the HTTP invokers for **one transfer** (`TRD 5.3`, `KASI-ENG-001`, `KASI-ENG-006`, `KASI-NFR-011`).

- **[changed] One `HttpHostPool` per `DownloadAsync` / `ResumeAsync` call, created and disposed by `HttpTransferRunner`.** Lanes are keyed `(origin, workerId)`; sharing one pool across jobs would put two jobs' worker 0 on the same single-connection lane and serialise them. The runner owns disposal of all lane handlers when the transfer ends. Per-host connection caps across jobs belong to the queue/engine facade (M1.13) and are noted in ADR 0006.
- **`HttpHostPoolOptions`:** `ConnectTimeout` 15 s, `PooledConnectionIdleTimeout` 2 min, `PooledConnectionLifetime` 15 min, `KeepAlivePingDelay` 15 s, `KeepAlivePingTimeout` 10 s, `EnableMultipleHttp2Connections = true`, and `internal X509Certificate2Collection? CustomTrustRoots` (visible only to `Kasi.Engine.Tests`). **No public property, callback or flag can disable or weaken certificate validation** (`KASI-NFR-011`).
- **[changed] How `CustomTrustRoots` validates test certificates without any callback (`TC-ENG-023`):**
  - Production (`CustomTrustRoots is null`): nothing is set; the OS default validation applies. The revocation mode stays at the framework default (no online revocation check) and is stated in ADR 0006, so the engine works offline.
  - Tests (`CustomTrustRoots` set): `SocketsHttpHandler.SslOptions.CertificateChainPolicy` gets an `X509ChainPolicy` with `TrustMode = CustomRootTrust`, the roots in `CustomTrustStore`, and `RevocationMode = NoCheck` (ephemeral certificates). **No `RemoteCertificateValidationCallback` is used**, so `SslStream` still enforces the host name and the time window itself: `Valid` passes, `Expired` fails with `NotTimeValid`, `SelfSigned` with `UntrustedRoot`, `WrongHost` with a name mismatch.
- **`SocketsHttpHandler` settings per lane:** `AllowAutoRedirect = false` (redirects are followed by `HttpProber`), `AutomaticDecompression = None`, `UseCookies = false`, `EnableMultipleHttp2Connections = true`, `MaxConnectionsPerServer = 1` (relevant to HTTP/1.1; an HTTP/2 lane serves one worker's sequential requests, so it uses one connection).
- **Why worker lanes (HTTP/2, `TC-ENG-002`, TRD 6.2):** one shared `SocketsHttpHandler` only opens a second HTTP/2 connection when the first reaches the server's `MAX_CONCURRENT_STREAMS` (100 on Kestrel and most CDNs), so 8 workers would multiplex on one TCP connection. Giving each worker its own lane means parallel segments get separate connections, and each worker reuses its connection for all its leases: `K` handshakes for `K` workers (`TC-ENG-010`).
- **[added] HTTP version:** `HttpHostPool` exposes `GetInvoker(Uri, int workerId)` and the requests built by `HttpProber` and the lease loop set `Version = HttpVersion.Version20` with `VersionPolicy = RequestVersionOrLower`, so TLS servers that offer h2 are used over HTTP/2 (production wants this too) and plaintext or h1-only servers fall back to HTTP/1.1. `HttpProber` gets this change in step 2, with its existing tests unchanged. Lease requests also keep `Accept-Encoding: identity`, as the prober does.

### 2.3 Step 4 (M1.7b) — `HttpTransferRunner`, `HttpTransferOptions`, & `TransferOutcome` (`src/Kasi.Engine/`)

Coordinates a download from URL (or resume state) to a verified file by driving `HttpProber`, `SegmentScheduler`, `PartFileWriter` and `PooledPartWriteBuffer`.

1. **Outcome and error types (`TransferOutcome.cs`):**
   - `TransferErrorKind`: `ProbeFailed` (carries the `ProbeFailure`; `ProbeErrorKind.CertificateError` maps to `CertificateError` in one place), `CertificateError`, `DiskNotEnoughSpace` (`.kasipart` and flushed cursors preserved), `DiskTargetExists`, `DiskError` (`IoError`, `PartFileMismatch`, `LengthMismatch`, `IncompleteData`), `HttpStatusError` (`HttpStatusCode`, optional `RetryAfter` for M1.8), `ProtocolError` (bad `Content-Range`, unexpected `200` on a ranged lease, truncated body, **[added]** probe body length differing from the first lease length), `TransientNetworkError`, **[added]** `FileChanged` (a `200` to an `If-Range` request, or a `206` whose `ETag` differs from the probe's), **[added]** `Cancelled`.
   - `TransferCompleted`: `FinalUrl`, `FileName`, `FinalPath`, `TotalBytes`, `RangesSupported`, `Resumable`, `ETag`, `LastModified`, `FinalSegments`, `StructureVersion`, `EndgameDuplicateBytes`.
   - `TransferFailed`: `ErrorKind`, `Detail` (diagnostic only, redacted with `Redact.Url` / `Redact.Path`), `BytesFlushed`, `SegmentsSnapshot`, plus the optional `ResolvedFileName`, `TotalBytes`, `ProbeFailure`, `DiskStatus`, `HttpStatusCode`, `RetryAfter`, **[added]** `ETag` and `LastModified` (so a resume can send `If-Range`).
   - **[added]** `FinalUrl` and `FinalPath` stay in memory only; callers must not log them (rule 3).
2. **`HttpTransferOptions`:** `SchedulerOptions`, `OverrideFileName`, `OverwriteDestination` (default `false`), `SpaceProvider`, `TimeProvider`, `WriteBufferMaxAge` (500 ms), `SupersededLeaseDrainTimeout` (15 s), `RequestHeaders` (tests: `X-Kasi-Chaos`). **[changed]** `OnStructureChanged` and `OnProgressBytes` are removed (see section 1).
3. **Execution flow (`HttpTransferRunner.cs`):**
   - **`DownloadAsync(Uri url, string destinationFolder, HttpTransferOptions? options = null, CancellationToken cancellationToken = default)`:**
     1. **Probe** on lane 0 with `firstRangeLength = options.SchedulerOptions.MinLeaseBytes` (512 KiB, ADR 0004). A `ProbeFailure` becomes `TransferFailed`.
     2. **[added] Early target check:** unless `OverwriteDestination`, an existing final file fails fast with `DiskTargetExists` before any bytes are downloaded. The commit-time `TargetExists` stays as the race guard.
     3. **Open `.kasipart`** with `PartFileWriter.TryOpen(destinationFolder, fileName, probe.TotalBytes, resume: false, ...)`; a failure disposes the probe and returns `TransferFailed` (`NotEnoughSpace` becomes `DiskNotEnoughSpace`).
     4. **Single-stream mode** (`!probe.RangesSupported || probe.TotalBytes is null or <= 0`; covers `/norange`, `/chunked`, 0 B): streams `probe.Body` through one `PooledPartWriteBuffer` **[changed]** reading into the whole `AvailableWindow` (not 16 KiB), checks total bytes against `TotalBytes` when known (else `ProtocolError`), then `SealAsync(expectedLength: totalWritten, bytesWritten: totalWritten)` and `CommitAsync(options.OverwriteDestination)`.
     5. **Segmented mode** (`probe.RangesSupported && probe.TotalBytes is > 0`): `new SegmentScheduler(total, rangesSupported: true, options.SchedulerOptions, timeProvider, firstLeaseIsProbeStream: true)`, worker tasks `0 .. MaxConnections - 1`, and a 250 ms pulse (`PeriodicTimer` on `TimeProvider`) that calls `EvaluateRampUp()`.
        - **[added] Idle workers** wait on a signal (`SemaphoreSlim` or `Channel`) raised on lease completion, ramp-up growth and structure change; the pulse is only the backstop. Workers exit when `scheduler.IsComplete` or the transfer is cancelled or failed.
        - **Worker 0's first lease** (`IsInitialProbeStream`) reads from `probe.Body`, which already holds the bounded `206` (zero extra request, `TC-ENG-003`); the probe is disposed when that stream ends, returning connection 0 to lane 0.
        - **Other leases (`TransferLeaseAsync`):** `GET` on the worker's lane with `Range: bytes={Start}-{End-1}`, **[added] `If-Range: <ETag or Last-Modified>`** when the probe recorded one, and `ResponseHeadersRead`. Require `206`, a matching `Content-Range`, and **[added]** the same `ETag` as the probe; a `200` is `FileChanged`.
        - **Read loop:** `writeBuffer.BeginLease(start, end)`, then `ReadAsync(writeBuffer.AvailableWindow)` and `AdvanceBufferedAsync`. Whenever `FlushedBytes > 0`, `scheduler.AdvanceLease(leaseId, FlushedBytes)` and signal idle workers if more work became available.
        - **[added] Read to EOF:** a lease reads its response until the final read returns 0 before the response is disposed. Disposing early makes HTTP/2 send `RST_STREAM`, which Kestrel counts as an aborted request.
        - **Lease end:** normal end → `CompleteLeaseAsync`, `scheduler.CompleteLease`, dispose the response. `IsSuperseded` (an endgame peer won) → `DropSuperseded()`, `CompleteLease`, drain the rest of the bounded response (up to `SupersededLeaseDrainTimeout`) so the connection returns cleanly (`TC-ENG-011`).
     6. When `scheduler.IsComplete`: await all workers, `SealAsync(expectedLength: total, bytesWritten: scheduler.TotalWritten)` and `CommitAsync(options.OverwriteDestination)`.
   - **[changed] Failure and cancellation order (one code path, ADR 0003/0006):** (1) cancel the siblings; (2) each worker writes its pending buffer and advances its lease, or abandons it on failure; (3) **take the segment snapshot**; (4) `PartFileWriter.FlushAsync`; (5) dispose the writer **without** `Abandon()` so `.kasipart` stays; (6) return `TransferFailed` (kind `Cancelled` when the caller's token fired) with the snapshot and `BytesFlushed`. Pause and shutdown use the same path, so the caller can record cursors that were captured before the flush.
   - **`ResumeAsync(Uri finalUrl, string destinationFolder, string fileName, long totalBytes, string? eTag, string? lastModified, IReadOnlyList<Segment> existingSegments, HttpTransferOptions? options = null, CancellationToken cancellationToken = default)`** **[changed]**: at least one validator is required; with neither, the call is refused with `FileChanged` (a file with no validators is not resumable, TRD 6.1) instead of guessing. It reopens `<fileName>.kasipart` with `resume: true, alreadyWrittenBytes: existingSegments.Sum(s => s.Written)`, restores `SegmentScheduler(totalBytes, existingSegments, ...)`, sends every lease with `If-Range`, and runs the same loop through `SealAsync` and `CommitAsync`.

## 5. Decisions & Questions to Confirm

Items 1–4 come from the first draft and are kept (with changes marked). Items 5–10 are new from the review; **D5, D9 and D10 are settled** (you left them to my judgement, and I chose the recommendations below); D6 to D8 apply by default unless you say otherwise.

1. **D1 — separate connection per worker over HTTP/2:** lanes `(origin, workerId)`, each `SocketsHttpHandler` with `EnableMultipleHttp2Connections = true`. **[changed]** The pool is per transfer, not shared across jobs.
2. **D2 — testing TLS without a bypass:** `internal CustomTrustRoots`. **[changed]** Implemented through `SslOptions.CertificateChainPolicy` with `CustomRootTrust`, no validation callback.
3. **D3 — no aborted requests when an endgame peer wins:** bounded leases, drop the buffer, drain the rest of the bounded response within `SupersededLeaseDrainTimeout`. **[added]** Normal leases also read to EOF before disposal.
4. **D4 — 1 GiB tests in CI:** run sequentially on the x64 job, expected hashes cached. **[changed]** Roughly 8 GiB of writes for the full count sweep is too much for every PR, so the sweep uses 256 MiB.
5. **D5 — settled: three PRs (M1.7a, b, c)** instead of one, each from `main` and merged before the next. One PR would mix a test-server rewrite, TLS validation and the transfer loop, which is too much to review with two approvals required.
6. **D6 — `InitialConnections = N` in the connection-count tests,** with a separate throttled ramp-up test, because the 250 ms ramp cannot reach 8 or 32 on loopback.
7. **D7 — `If-Range` and `ETag` checks from M1.7 on,** with a `FileChanged` outcome; M1.9 owns the policy.
8. **D8 — first lease failure ends the transfer in M1.7;** retry arrives with M1.8 through the single `TransferLeaseAsync` seam.
9. **D9 — settled: the `TC-ENG-006` sweep uses 256 MiB in PR runs** and the full 1 GiB sweep runs nightly (`Slow`, wired in M1.16). This is a deliberate deviation from the TPL's 1 GiB per count; the gate report cites the nightly 1 GiB run as the evidence. The 1 GiB `TC-ENG-001`, `002` and `010` tests still run on every PR.
