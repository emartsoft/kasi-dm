## 2. Proposed Design & Public API (`src/Kasi.Engine/`)

All types live in `Kasi.Engine` with no new NuGet dependencies. Expected download outcomes are represented as result types rather than exceptions (CONTRIBUTING 3.1), and any URL included in an error message is redacted via `Redact.Url` (`KASI-NFR-013`).

### 2.1 `ProbeOutcome`, `ProbeResponse`, and `ProbeFailure`

- **`ProbeOutcome`** (`src/Kasi.Engine/ProbeOutcome.cs`): abstract record with two sealed cases:
  - **`ProbeResponse`** (`src/Kasi.Engine/ProbeResponse.cs`, implements `IAsyncDisposable` and `IDisposable`). **[changed]** A sealed **class**, not a record: it owns a stream, and record equality and `with` copies would compare and share it.
    - `Uri FinalUrl`: final URL after redirects (or initial URL if no redirects occurred).
    - `long? TotalBytes`: total file size in bytes (`Content-Range.Length` on `206`, `Content-Length` on `200`, or `null` when unknown/chunked).
    - `bool RangesSupported`: `true` only when the server answered `206 Partial Content` with a valid `Content-Range: bytes 0-N/Total` (`Total > 0`); `false` on `200 OK` (single connection).
    - `bool Resumable`: `RangesSupported && (ETag is not null || LastModified is not null)` (`KASI-RES-005`).
    - `string? ETag`: strong `ETag` header value as sent by the server (e.g. `"\"seed-1000\""`). Weak tags (`W/"..."`) are excluded because RFC 9110 §13.1.5 forbids weak entity tags in `If-Range` and `.NET`'s `RangeConditionHeaderValue` rejects them.
    - `string? LastModified`: raw `Last-Modified` header string exactly as the server sent it, so `If-Range` can echo it unchanged (`Job.LastModified`).
    - `string? AcceptRanges`: raw `Accept-Ranges` value if present (`"bytes"`, `"none"`, etc.).
    - `string? ContentType`: media type (`response.Content.Headers.ContentType?.MediaType`, e.g. `"application/octet-stream"`).
    - `string FileName`: safe filename resolved via `DownloadFileName.Resolve(FinalUrl, contentDispositionHeaders)`.
    - **[added]** `long BodyLength`: the number of bytes the `Body` will deliver (`Content-Length` of the response, which is `N + 1` on a `206` for `bytes 0-N/Total`, and `null`-able when chunked). The caller must not assume `Body` holds the whole file.
    - **[added]** `string? ContentEncoding`: the response's `Content-Encoding` when it is not `identity`. A non-identity encoding makes the result `RangesSupported = false` and `Resumable = false` (see 2.2).
    - `Stream Body`: the open response stream positioned at byte 0 so segment 0 continues streaming without a second request (`TC-ENG-003`). Disposing `ProbeResponse` disposes both `Body` and the underlying `HttpResponseMessage`. **[added]** Ownership rule documented on the type: whoever receives a `ProbeResponse` must dispose it, including on every failure path of the caller; `ProbeAsync` disposes it itself if the caller's token is cancelled after the headers arrive.
    - `Job ApplyTo(Job job, bool preserveExistingFileName = false)`: returns a copy of `job` with `FinalUrl`, `FileName`, `TotalBytes`, `ETag`, `LastModified`, and `Resumable` populated.
  - **`ProbeFailure`** (`src/Kasi.Engine/ProbeFailure.cs`):
    - `ProbeErrorKind Kind`: `AuthRequired` (`401`, `403`, `407`), `PermanentError` (`404`, `410`, other non-retryable `4xx`, including `400`), `Throttled` (`429`, `503` with `Retry-After`), `TransientError` (`408`, `500`, `502`, `503`, `504`, DNS, connection and timeout errors), `TooManyRedirects` (> 10 hops), `InvalidRedirect` (missing/invalid `Location` or non-`http`/`https` scheme), `ProtocolError` (e.g. `206` with missing/non-zero `Content-Range`, or `416` after range-less re-probe). **[added]** `CertificateError` (TLS validation failed; permanent, no retry, TRD 6.6 and `KASI-NFR-011`).
    - `HttpStatusCode? StatusCode`: HTTP status code if a response was received.
    - `TimeSpan? RetryAfter`: parsed `Retry-After` delta (or date relative to `TimeProvider.GetUtcNow()`) when present on `429`/`503`.
    - **[added]** `IReadOnlyList<string> AuthChallenges`: the `WWW-Authenticate` schemes (`Basic`, `Digest`, …) on a `401`, which M1.10 needs to pick the credentials to send.
    - `string Message`: human-readable error message with URLs redacted via `Redact.Url`.

### 2.2 `HttpProber` (`src/Kasi.Engine/HttpProber.cs`)

- `public const int MaxRedirects = 10;`
- Constructor: `public HttpProber(HttpMessageInvoker httpClient, TimeProvider? timeProvider = null)` (uses `HttpClient` configured with `AllowAutoRedirect = false` so redirect hops, scheme validation, `FinalUrl` tracking, and future M1.10 host-scoped cookie stripping are under the engine's control). **[added]** The invoker must also have `AutomaticDecompression = None`; both are documented preconditions (the prober cannot inspect the handler). M1.7's per-host `SocketsHttpHandler` pool will supply a correctly configured invoker.
- **[changed]** `public Task<ProbeOutcome> ProbeAsync(Uri url, long? firstRangeLength = null, CancellationToken cancellationToken = default)`. `firstRangeLength = null` sends `Range: bytes=0-` as TRD 6.1 and TPL `TC-ENG-003` say. A value sends `Range: bytes=0-{firstRangeLength-1}` instead (see decision D1: how segment 0's stream meets the lease design in M1.5).
- **Probe flow:**
  1. Validates that `url` is an absolute `http` or `https` URI.
  2. Loops up to `MaxRedirects` (10) redirect hops:
     - Sends `GET` with `Range: bytes=0-` (unless re-probing after `416`) **[added]** and `Accept-Encoding: identity`, using `HttpCompletionOption.ResponseHeadersRead`.
     - **On `301`, `302`, `303`, `307`, `308`:** disposes the response, resolves `Location` against the current URI, rejects missing `Location` or non-`http`/`https` target schemes (`InvalidRedirect`), increments hop count (returning `TooManyRedirects` if `hops > MaxRedirects`), and continues.
     - **On `416 Range Not Satisfiable` (when `Range` was sent):** disposes the `416` response and re-probes `currentUri` once without a `Range` header (handles 0-byte files on range-capable servers, TRD 6.1).
     - **On `206 Partial Content`:**
       - Validates `Content-Range` (`Unit == "bytes"`, `From == 0`). **[changed]** `Length is > 0` gives `TotalBytes = Length`; a `*` length (legal: complete length unknown) gives `RangesSupported = true` with `TotalBytes = null`, so the engine uses one connection. A missing or malformed `Content-Range`, or `From != 0`, disposes the response and returns `ProtocolError`.
       - Extracts validators, headers, filename, opens the response stream, and returns `ProbeResponse` (`RangesSupported = true`).
     - **On `200 OK`:**
       - If `Transfer-Encoding: chunked` or `Content-Length` is absent: `TotalBytes = null`, `RangesSupported = false`, `Resumable = false`.
       - Otherwise: `TotalBytes = contentLength`, `RangesSupported = false`, `Resumable = false`.
       - **[added]** A non-identity `Content-Encoding` on either `200` or `206` also forces `RangesSupported = false` and `Resumable = false` and sets `ContentEncoding`, because ranges would address the encoded bytes and we do not decode.
       - Opens the response stream and returns `ProbeResponse`.
     - **On `401`, `403`, `404`, `410`, `429`, `5xx`, or `HttpRequestException`:** disposes any response and maps to the corresponding `ProbeFailure`. **[added]** `HttpRequestException.HttpRequestError` decides the kind (`SecureConnectionError` → `CertificateError`; `NameResolutionError`, `ConnectionError`, … → `TransientError`).
     - **[added]** **Cancellation and timeouts:** if the caller's token is cancelled, `OperationCanceledException` propagates; a `TaskCanceledException` while the caller's token is not cancelled is an `HttpClient` timeout and becomes `TransientError`.

## 6. Decisions and resolved questions

**Decisions needed (defaults in bold):**

- **D1, segment 0's stream.** TRD 6.1 keeps streaming the probe response as segment 0, but TRD 6.2 and 6.3 say a split never cuts into a lease in flight. An open-ended `Range: bytes=0-` stream is a lease over the whole file, so the scheduler could never split it, and aborting it mid-stream would close the connection and defeat connection reuse (TC-ENG-010). **Keep `bytes=0-` as the TRD and TPL say, add the optional `firstRangeLength` parameter now, and let the M1.5 scheduler design (with its own ADR) decide how the probe stream becomes the first lease.**
- **D2, content encoding.** **Send `Accept-Encoding: identity`; a non-identity `Content-Encoding` means single connection and non-resumable.**
- **D3, unknown total on a `206`.** **Accept `Content-Range: bytes 0-N/*` as ranges supported with unknown size (single connection) instead of `ProtocolError`.**

**Resolved:**

1. **Branching:** M1.4 uses `DownloadFileName` from M1.3, which is in PR #13. **Merge #13 to `main` first, then branch `feature/m1-4-probe` from `main`**; stacking made the squash merges conflict in M0.
2. **`HttpClient` configuration:** the `HttpMessageInvoker` constructor is fine. `AllowAutoRedirect = false` and `AutomaticDecompression = None` are documented preconditions; M1.7's per-host `SocketsHttpHandler` pool will supply the invoker.
