## 2. Proposed Design & Public API (`src/Kasi.Engine/`)

All types live in `Kasi.Engine` with no new external dependencies. British spelling follows the specs ("Sanitise"). **[added]** Every entry point first bounds its input (header 16 KiB, URL path and candidate name 4 KiB) so nothing allocates without limit (TPL 7.2).

### 2.1 `ContentDispositionParser` (`src/Kasi.Engine/ContentDispositionParser.cs`)

- **[changed]** `public static bool TryGetFileName(string? headerValue, out string fileName)` (plus an overload accepting `IEnumerable<string>?` for multi-header responses). A `Try*` method returns `bool` with an `out` value, as elsewhere in the codebase.
- **Parameter splitting:** Quote-aware semicolon scanner so `;` inside `"a;b.txt"` does not split the parameter.
- **Precedence (RFC 6266 §4.3):**
  - Prefers `filename*` over `filename` regardless of parameter order.
  - Parses RFC 5987 / 8187 `ext-value` (`charset'language'pct-encoded`), supporting `UTF-8` and `ISO-8859-1` (case-insensitive). Rejects malformed `ext-value` (missing `'` delimiters or unsupported charset) and falls back to `filename`.
- **Quoted-string handling (`filename="..."`):**
  - Unescapes `\"` → `"` and `\\` → `\`, while preserving single backslashes before other characters so unescaped Windows paths (`filename="C:\Windows\...\hosts"`, `filename="..\..\evil.txt"`) keep their path separators for leaf extraction rather than mangling `\W` or `\.`.
- **Safety:** Bounds input length (ignores headers > 16 KiB) and never throws on malformed input.

### 2.2 `FileNameSanitiser` (`src/Kasi.Engine/FileNameSanitiser.cs`)

- `public const int MaxLength = 200;`
- `public const string DefaultFileName = "download";`
- `public static string Sanitise(string? candidate, string fallback = DefaultFileName)`
- **Pipeline:**
  1. **Path & traversal stripping (RFC 6266 §4.3 / TRD 13.1):**
     - Extracts only the substring after the last `/` or `\` (a trailing slash like `"../../"` yields empty rather than `".."`).
     - Strips any leading Windows drive prefix (e.g., `"C:evil.txt"` → `"evil.txt"`).
     - Rejects `"."` and `".."` (treated as empty → fallback).
  2. **Control, bidirectional and invalid characters:**
     - Strips Unicode control characters (`U+0000`–`U+001F`, `U+007F`–`U+009F`).
     - **[added]** Strips bidirectional control characters (`U+202A`–`U+202E`, `U+2066`–`U+2069`), which are format characters, not control characters, and are used to spoof extensions (`invoice‮fdp.exe`). Other format characters are kept so emoji with joiners survive.
     - Replaces Windows invalid filename characters (`<`, `>`, `:`, `"`, `|`, `?`, `*`) with `_`.
  3. **Trimming:**
     - Trims leading whitespace and all trailing dots (`.`) and whitespace (Win32 path normalisation safety, e.g., `"report.txt. . "` → `"report.txt"`).
  4. **Windows reserved device names:**
     - Checks the stem before the first `.` (case-insensitive) against `CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`, `CONIN$`, `CONOUT$`, and superscript variants (`COM¹`/`²`/`³`, `LPT¹`/`²`/`³`).
     - **[added]** The stem is compared after trimming trailing spaces and dots, so `"NUL .txt"` and `"CON. .txt"` are caught as well.
     - Maps matches by prefixing `_` (`"CON.txt"` → `"_CON.txt"`, `"NUL"` → `"_NUL"`).
  5. **200-character cap (surrogate-safe, extension-preserving):**
     - If length > 200, preserves a trailing extension (up to 32 chars) and truncates the stem so total `Length <= 200`, without splitting a UTF-16 surrogate pair and re-trimming any trailing dots/spaces exposed on the stem. The reserved-name check is repeated after truncation.
  6. **Fallback:** If the result is empty after steps 1–5, returns `fallback` (`"download"`).

### 2.3 `DownloadFileName` (`src/Kasi.Engine/DownloadFileName.cs`)

- `public static string Resolve(Uri? url, string? contentDisposition = null)` (and `Resolve(string? url, string? contentDisposition = null)`):
  1. Tries `ContentDispositionParser.TryGetFileName(contentDisposition, out var name)` → sanitises it; if usable, returns it.
  2. Otherwise extracts the last segment of `url.AbsolutePath` (ignoring `?query` and `#fragment`), safely percent-decodes it (without throwing on invalid `%` sequences), and sanitises it.
  3. Otherwise returns `"download"`.
- **[added]** **Latin-1 → UTF-8 repair:** .NET decodes response header bytes as Latin-1, so a server that sends UTF-8 raw in `filename=` produces mojibake (`â‚¬ rates.txt`). When every character of the parsed name is ≤ `U+00FF` and the bytes form valid UTF-8, the name is re-decoded as UTF-8 (the browser heuristic). Applies only to the plain `filename` parameter, never to `filename*`.

## 4. Verification & Fuzz Target (`tests/Kasi.Engine.Tests/`)

`Kasi.Engine.Tests` gets a project reference to `Kasi.TestServer` (to read `DispositionEndpoints.Cases` and start `TestServerHost`).

1. **Unit tests (`ContentDispositionParserTests`, `FileNameSanitiserTests`, `DownloadFileNameTests`):**
   - Tagged with `[Trait("TC", "TC-ENG-004")]`, `[Trait("TC", "TC-ENG-005")]`, and `[Trait("Requirement", "KASI-ENG-003")]`.
   - Verifies all 16 `DispositionEndpoints.Cases` plus additional RFC 6266 / 5987 edge cases (`ISO-8859-1`, language tags, reversed parameter order, unquoted tokens, malformed `%` encodings, surrogate pairs at the 200-char boundary, URL paths with queries/fragments/trailing slashes).
   - **[added]** Bidi controls (`invoice‮fdp.exe`), `NUL .txt` and `CON. .txt`, the Latin-1 → UTF-8 repair (and that `filename*` is never repaired), and the input bounds.
   - Verifies the security invariant for every case: `Path.GetFullPath(Path.Combine(targetDir, resolved))` is strictly inside `targetDir` and `resolved.Length <= 200`.
2. **[added] Integration test (`Category=Integration`):** every `/disposition/{case}` is fetched from a real `TestServerHost` with `HttpClient`; the raw header value (`response.Content.Headers.GetValues`) goes through `DownloadFileName.Resolve` and is compared with the table in section 3. A **drift guard** fails when `DispositionEndpoints.Cases` contains a key without an expected name.
3. **Fuzz target & seed corpus:**
   - Reusable fuzz target entry point + seed corpus in `tests/fixtures/disposition-corpus/` (RFC 6266 examples and traversal strings per TPL 7.2) and a seeded randomised fuzz test in `Kasi.Engine.Tests` that runs thousands of mutated inputs and asserts: no exception thrown, length in `[1, 200]`, no path separators or control characters, and stays inside the target folder. The seed is printed on failure (CONTRIBUTING 4). The nightly `SharpFuzz` runner wiring remains in M1.16. No FsCheck is added here; it arrives with the segment property tests in M1.5.
4. **Update `plan.md`:** Tick `M1.3` once all tests and `dotnet format --verify-no-changes` pass.
