# M2.4 Plan — Browser download interception (`extension/`, end-to-end harness)

- **Phase:** M2 — Browser integration, queues, categories, main UI ([`plan.md`](../../plan.md) section 5)
- **Requirements:** `KASI-BRW-002`, `KASI-BRW-003`, `KASI-BRW-006` (the disconnected state after a failed hand-off), `KASI-NFR-010`, `KASI-NFR-015` ([`KASI-TRD-2026-001.md`](../specs/KASI-TRD-2026-001.md) sections 9.1 to 9.4, 15.2)
- **Test cases:** `TC-BRW-001`, `TC-BRW-002` (the extension half; the host half is M2.2a), `TC-BRW-003`, `TC-BRW-004` ([`KASI-TPL-2026-001.md`](../specs/KASI-TPL-2026-001.md) section 5.3). Extension tests carry the ID in the title (`[TC-BRW-003] …`) and run with `vitest -t "TC-BRW-003"`; the C# harness tests use `[Trait("TC", …)]`. `TC-BRW-005` and `008` are M2.5; `TC-BRW-007` is M2.6.
- **ADR:** `docs/adr/0019-browser-download-interception.md` (rule semantics, the hand-off budget, bypass detection, the end-to-end harness).
- **Dependencies:** **none new in `extension/`.** `webextension-polyfill`, Vitest and `playwright` (library) are already there. The Firefox driver is a small WebDriver client over `fetch` talking to `geckodriver` (MPL-2.0, a development tool found on the CI runner, never shipped, the same footing as `web-ext`). The C# harness references `Kasi.Ipc` and `Kasi.TestServer` only. Anything else is flagged in section 6 before use.
- **Depends on:** M2.1 (messages, `KasiPipeServer`), M2.2a (host and registration script) and M2.3 (port manager, rules cache, logger, manifests) are merged. M2.2b (fuzz, AOT in CI) runs in parallel and does not touch what this plan needs; **this plan changes nothing under `src/Kasi.NativeHost` or its tests.**
- **Delivery:** three PRs, one after the other. **2.4a** rule semantics and, if approved (decision 1), the optional `minSizeBytes` on `rules` with its C# side. **2.4b** the interception logic, bypass detection, native-port fixes and unit tests. **2.4c** the end-to-end harness, the Chromium and Firefox tests, CI. If decision 1 is "no", 2.4a folds into 2.4b.
- **Status:** draft; awaiting approval.

## 2. Scope and decisions

2.4 turns the M2.3 scaffold into working interception. The M2.3 modules stay; new logic is split into small pure modules with injected `browser` APIs, so every branch is a Vitest case and the browsers are only needed for the end-to-end proof.

### 2.1 Rules (`rules-match.ts`, `docs/protocol/README.md`)

Semantics (written into the protocol README and TRD 9.2 in 2.4a, so Kasi and the extension agree):

- **Intercept** when `enabled` and the download passes the exclusions (2.5) and **(extension matches or MIME matches)**.
- **Extensions:** lowercase, no leading dot, compared with the end of the file name (`tar.gz` matches `a.tar.gz`). **MIME:** lowercase, exact, or `type/*`; parameters are ignored. **Empty lists match nothing** (fail safe: never take what was not asked for), so a fresh Kasi must push a populated default.
- **`excludedSites`:** an entry `example.com` matches that host and its subdomains. It is tested against the host of the URL, the final URL **and** the referrer; any hit excludes. The exclusion runs **before** cookies are read.
- **Minimum size (decision 1).** Recommended: add optional `minSizeBytes` (integer, 0 to 2^53-1) to `rules`. A strict parser on an old extension rejects the whole message, so Kasi sends the field only when `hello.extensionVersion` is new enough; no `v` bump. Size comes from `DownloadItem.totalBytes` when known; an unknown size (`-1`) **is intercepted**, because Kasi learns the size itself and the user can decline in its dialog.
- **No rules yet** (fresh install, Kasi never reached): nothing is intercepted. The rules in use are the last `rules` message in memory, else the `storage.local` cache, so a stopped worker or event page decides the same way.

### 2.2 The hand-off and its time budget (`interception.ts`)

```text
onCreated(item)
  ├─ exclusions / rules do not match / bypass held ─────────────► do nothing (the browser downloads)
  ├─ state != in_progress, or pause() rejects ──────────────────► do nothing
  └─ match: pause()
        ├─ port state "host missing" or APP_NOT_INSTALLED ──────► resume (nothing waited for)
        ├─ not connected: reconnect now, wait ≤ 6 s for rules ──► if none: resume, badge "disconnected"
        └─ connected: addDownload + cookies, wait ≤ ackTimeoutMs (default 2 s)
              ├─ ack ──► cancel(), erase()  (+ removeFile on Firefox if a part file is left)
              └─ error / timeout / disconnect ──► resume() if still paused, badge "disconnected"
```

- **Two phases (G1).** *Ready* (host launch window of 5 s plus the `hello`/`rules` round trip, 6 s total, one constant) applies only when the port is not connected. *Ack* is `rules.ackTimeoutMs` (default 2000), counted from the moment `addDownload` is posted. The browser download is paused at most about 8 s, and only when Kasi was not running. A host registered but Kasi not installed (`APP_NOT_INSTALLED`) or no host at all (the port dies at once with "not found") pauses nothing, so a machine without Kasi never slows a download.
- **Pause first (TRD 9.2).** Pause happens right after the match, before cookies are read. If the item is already complete (a tiny file) or `pause` rejects, the download is left alone. A resume checks `downloads.search({ id })` first: a download the user cancelled meanwhile is not resumed.
- **Port changes in `native-port.ts` (2.4b):** `connected` becomes true only on `rules` (Kasi is alive) and false on `APP_NOT_RUNNING` / `APP_NOT_INSTALLED` (G2); the manager exposes `lastFailure` (`host-missing`, `app-not-installed`, `app-not-running`), `reconnectNow()` (resets the backoff) and `whenConnected(timeoutMs)`.
- **Concurrency.** Each download runs its own flow; ids come from the port manager. Twenty clicks produce twenty independent paused downloads, each with its own timeout.

### 2.3 Acknowledgement semantics (G13, decision 5)

`ack` for `addDownload` means **Kasi has durably accepted the request** (the job exists, or the add dialog is queued), not that the user confirmed a dialog; otherwise a slow user always trips the 2 s timeout. This is a requirement on the M2.8 handler and is written into TRD 9.4 and the protocol README in 2.4a. A request id is idempotent on Kasi's side; the extension never retries. A **late ack** (after the timeout, download already resumed) is remembered for 30 s by id and, if that browser download is still in progress, it is cancelled and erased, so one file is not downloaded twice. If the bytes are already complete, nothing is done and Kasi's duplicate prompt (`ENG-013`) handles it.

### 2.4 Bypass key (`KASI-BRW-003`, `content/modifier.ts`, `bypass.ts`)

`onCreated` cannot see the keyboard (G5), so the page tells the background.

- **Content script (all frames, `document_start`, `match_about_blank`).** Capture-phase listeners for `pointerdown`, `click`, `auxclick` and `keydown` (Enter on a focused link), trusted events only (`isTrusted`; a page cannot fake a bypass, and a bypass only ever makes the browser keep its own download, so it fails safe). When Alt, Ctrl or Shift is held it sends `{ kind: 'kasi-modifier', mods, href }` (the closest anchor's resolved URL when there is one). Nothing is sent for plain clicks.
- **Background.** Records the last modifier event with its time, tab and the SHA-256 of `href` (a hash, so no URL is stored), in memory and `storage.session`. At a match it pauses first, then waits a **100 ms grace** if no record exists yet (the message and the first byte race on a fast local server), then bypasses when the record names the configured `rules.bypassKey` and is fresh: **15 s** when `href` equals the download's URL, final URL or a redirect hop seen by `webRequest` (a slow server may take that long to answer after the user released the key), otherwise **3 s**. `bypassKey: none` disables it.
- **Downloads that start outside a page** (address bar, bookmark, "Save link as…" from the browser's own menu, another application, restricted pages where no content script runs: `chrome://`, the Web Store, the PDF viewer, `file://` without access, a Firefox install with the host permission denied) **cannot be bypassed by a modifier**: there is no event to read. They are intercepted. The escape hatches are `excludedSites` and, with the key, any ordinary page. A native `GetAsyncKeyState` query in the host was considered and rejected: the key is usually released before `onCreated`, it needs a new message and a P/Invoke in an AOT host, and it would not meet the "Alt-click in the page" acceptance any better. The limitation is documented in the extension README and the store text.
- **Alt-click is the browser's own "download this link"** on Windows, which is why Alt is the default; the tests cover Alt and, to isolate key detection from that native feature, Ctrl and Shift on `<a download>`.

### 2.5 Exclusions (`TC-BRW-004`, `classify.ts`, `request-tracker.ts`)

Never intercepted, checked before any pause:

- **Scheme:** the URL and final URL must be `http`, `https` or `ftp` (`ftps` is accepted by the schema but no browser produces it). `blob:`, `data:`, `file:`, `filesystem:`, `about:` and anything else are skipped. A URL over 8,192 characters is skipped.
- **Another extension's download** (`item.byExtensionId` set, including ours): skipped, so there is no loop.
- **POST-form downloads.** `DownloadItem` has no method, so `request-tracker.ts` listens (non-blocking `webRequest.onBeforeRequest`, `main_frame` and `sub_frame`) and remembers requests whose method is not `GET`, following `onBeforeRedirect` so a `POST → 302 → GET` chain stays marked. Entries live 30 s, are capped at 64, keyed by a URL hash, and written through to `storage.session` so a stopped worker or event page still knows them. A hit on the URL or final URL means "do not intercept". This uses the `webRequest` permission the manifest already holds.
- **Incognito.** `item.incognito` is skipped unless the user switched the extension on for private windows (`isAllowedIncognitoAccess()`; the browser's own toggle is that switch, and both browsers send no private-window events without it). When allowed, cookies are read from that window's store (`getAllCookieStores` plus the tab's store). Caveat for the owner (decision 6): a job in Kasi is persisted with its URL and cookies, which a private window's user may not expect.
- **Missing host permission** (Firefox lets the user revoke `<all_urls>`): cookies and `webRequest` would silently return nothing, so interception is off, the popup already shows "needs permission" (M2.3b) and the browser downloads normally.

### 2.6 `addDownload` and cookies (`cookies.ts`, `build-add-download.ts`)

- Fields: `url`, `finalUrl`, `referrer` (omitted when empty or not a valid web URL), `filename`, `mime`, `userAgent` (`navigator.userAgent`), `cookies`. The file name is a **hint**: the basename of `item.filename`, else the last URL path segment, else `download`; it is cut to 255 characters keeping the extension. Kasi's engine resolves the real name from the response, so the extension does not wait for Chromium's `onChanged` file name.
- **Cookies** come from `cookies.getAll` for the URL **and** the final URL (a redirect can cross domains), de-duplicated by name, domain and path, with the right `storeId`. `domain` is passed **unchanged**: the leading-dot convention of both browsers (`.example.com` for a domain cookie, `example.com` for host-only) is the only `hostOnly` signal the protocol has (G10); Kasi's job scope relies on it and a test asserts it. A cookie value over 4,096 characters is dropped; over 200 cookies keeps the 200 with the longest paths. Cookies are read **only after** a match and the exclusions, never for a download that is left alone.
- The message is validated against the generated type and, in tests, against the schema, before it is posted.

### 2.7 Status and the disconnected state (`BRW-006`, G2)

After any failed hand-off the extension sets a red `!` badge (`action.setBadgeText`, text from `_locales`) and the popup shows the existing "not connected" text; a `rules` message clears it. The 5-second status timer, the context menus and the picker stay in M2.5.

### 2.8 Chromium and Firefox

| Point | Chromium (service worker) | Firefox (event page) |
| --- | --- | --- |
| Lifetime | Idle worker stops after about 30 s; an open `connectNative` port and pending extension API calls keep it alive for the whole 8 s hand-off. State that must survive (rules, modifier record, POST marks) is in `storage.local` / `storage.session` | Event page suspends when idle; the same state rules apply. Whether a native port keeps it alive is **verified in 2.4c**, not assumed |
| Listeners | Registered synchronously at the top level (already the M2.3 rule), including the new `downloads`, `webRequest` and `runtime.onMessage` ones | Same |
| Event order | `webRequest` → `downloads.onCreated`; `onCreated` can fire before the file name is known | `onCreated` can arrive before `webRequest` completes; the tracker needs only `onBeforeRequest` |
| `DownloadItem` | `incognito`, `referrer`, `byExtensionId`, `totalBytes` | the same fields; cookie store comes from the tab |
| Permission | `<all_urls>` granted at install | granted at install but revocable: the M2.3b "Allow Kasi on all sites" step gates interception |
| Cleanup | `cancel` removes the part file | `cancel` may leave one: `removeFile` in a `try`, and the e2e test asserts the folder is empty |
| Private windows | extension "Allow in Incognito" | "Run in Private Windows" |

### 2.9 Out of scope, and the seam left for it

`refreshLink` handling (G9) and the toolbar toggle (G11) are not built here. The interception handler runs `claims: Claim[]` before the rules (a refresh watcher can claim a download first), empty in 2.4, so the later work does not reorder the pipeline.

## 3. What the end-to-end tests need

### 3.1 C# side (2.4c; no change to host sources)

The real Kasi cannot be used: it has no `addDownload` handler until M2.8 and no `--tray`. The real pipe, framing, ACL and host **are** used.

```text
tests/Kasi.BrowserHarness/                 console app: Kasi.Ipc + Kasi.TestServer only
├── Program.cs                             `serve` (default) and `--tray` (acts as Kasi.exe; see below)
├── StubKasi.cs                            KasiPipeServer at \\.\pipe\kasi-<SID>; hello -> rules; addDownload -> ack | error | silence | delay
├── PageServer.cs                          the e2e pages: links, <a download>, POST form, blob: and data: generators
└── AdminApi.cs                            loopback HTTP: POST /_stub/rules|mode, GET /_stub/received, GET /_stub/ready
```

- It starts `Kasi.TestServer` in-process (`/files`, `/auth/cookie`, chaos latency for slow answers) and prints a JSON line with the ports. `AdminApi` is how Node reads what the stub received (no named pipes from Node).
- **TC-BRW-002 chain, for real:** the test copies the harness to `Kasi.exe` **next to** `Kasi.NativeHost.exe` and starts with no pipe. The host's `AppLauncher` runs `Kasi.exe --tray`; the harness opens the pipe after a delay and the download must be taken. "Kasi missing" = no sibling `Kasi.exe` (`APP_NOT_INSTALLED`). "Not acknowledged" = stub mode `silent`.
- **Small addition to `tests/Kasi.TestServer`** (ADR 0001 updated): a POST endpoint that answers with a `Content-Disposition: attachment` file, which the POST-form case of `TC-BRW-004` needs. `/files` already serves `application/octet-stream`, which browsers download.
- **Registration safety (G12).** The test registers the host under HKCU for the browser under test, **saves the previous value and restores it** in `finally`, and refuses to run if a real Kasi owns the pipe or if `KASI_E2E` is unset (CI sets it; a developer opts in). `Register-NativeHost.ps1` gains a `-Browser Chromium` target (`HKCU\Software\Chromium\NativeMessagingHosts`, to be confirmed in the 2.4c spike). The pipe name is **not** made configurable: a test-only override in a production host is a security regression.
- **Deterministic extension ID.** The e2e build injects a fixed test public `key` into `dist/chromium/manifest.json` (env `KASI_E2E_KEY`), so the host manifest's `allowed_origins` is known before the browser starts; `check-manifests` fails if `key` appears in a build made without that variable. The Firefox ID is already fixed.

### 3.2 Playwright and Firefox (G6)

- **Runner:** Vitest with a second config (`vitest.e2e.config.ts`, `npm run test:e2e`) driving the existing `playwright` library, so no new dependency and the same `[TC-…]` titles. (`@playwright/test` would be a new dev dependency; decision 3.)
- **Chromium:** persistent context with the unpacked extension, as the M2.3b smoke does. A **spike first**: Playwright takes over browser downloads (`Browser.setDownloadBehavior`), which may stop `downloads.onCreated` firing or cancel the item. Fallback if so: launch Chromium ourselves and drive it with chromedriver through the same WebDriver client as Firefox.
- **Firefox:** `geckodriver` through a ~100-line WebDriver-classic client over `fetch`: new session with prefs (download folder, no prompt), `POST /session/:id/moz/addon/install` with `temporary: true`, page navigation, element click, and the W3C actions API for Alt-click. Firefox reads the registry key already written, and a fresh profile per run keeps cookies clean. `geckodriver` and Firefox are on the GitHub Windows image; the README says how to get them locally. This also finishes the Firefox popup check that `extension/README.md` promised for M2.4.
- **Assertions are browser-agnostic:** what the stub received (`/_stub/received`), the files left in the download folder and their SHA-256 (`GeneratedContent.Sha256Hex`), and the popup/badge text. Only the driver differs per browser.

### 3.3 Browsers in the matrix (G7)

Automated: Playwright's Chromium (stands in for Chrome and Edge, the same bundle) and Firefox release. Branded Chrome and Edge are in the release-candidate matrix by hand (TPL section 4, Hyper-V), with the steps of `TC-BRW-001` to `004` as a checklist in `docs/qa/`; if the spike shows `channel: 'msedge'` still loads unpacked extensions, it joins the nightly matrix. The alpha gate text "passes in Chrome, Edge and Firefox" is met by the nightly (Chromium, Firefox) plus that manual run, and the 2.4c PR says so.

## 6. Security and privacy

- **Cookies are secrets.** They are read after a match only, held in memory for the length of one hand-off, sent once to the local host, never put in `storage`, never in an error, a badge, a log or a message detail; the redaction tests above prove it. Kasi stores them with DPAPI (`M1.10`) and deletes them with the job (M2.12).
- **The browser never loses a download:** a download is cancelled only after an ack; every other path resumes it. The late-ack cancel (2.3) acts only on a download still in progress.
- **Trust.** Only messages from our own extension (`sender.id`) and only trusted DOM events count; the content script has no access to cookies or the native port, and a page cannot reach the background. Everything the extension receives from Kasi still goes through `messages.ts`.
- **Store at rest:** hashes only (modifier record, POST marks), cleared with the session.
- No new permission, no new host permission, no remote code.

## 7. Open decisions (recommendation first)

1. **Minimum size.** Add optional `minSizeBytes` to `rules`, sent only to extensions that declare a new enough `extensionVersion` (recommended), **or** drop the "minimum size" wording from `BRW-002` and let Kasi's dialog handle small files. The first needs 2.4a and a TRD edit.
2. **Pre-connection wait.** 6 s ready wait plus the 2 s ack (recommended; the pause is bounded at about 8 s, only when Kasi was not running) **or** a single 5 s total, which makes the launch case fragile.
3. **E2E runner.** Vitest over the existing `playwright` library (recommended, no dependency) **or** `@playwright/test` (Apache-2.0, a new dev dependency, nicer reports and fixtures).
4. **CI placement.** Chromium e2e on path-filtered PRs and both browsers nightly (recommended) **or** both on every PR (TPL 2.1 reading; roughly doubles the job time) **or** nightly only (a regression can sit a day).
5. **Ack meaning and late-ack cancel.** Ack on durable acceptance, and cancel a still-running browser download on a late ack (recommended) **or** ack after the dialog and a longer timeout (a slow click then falls back to the browser).
6. **Incognito.** Honour the browser's per-extension switch, default off, with a note in the options text (recommended, TRD wording) **or** never intercept private windows, even when enabled (safer for privacy, departs from the TRD).
7. **Who builds `refreshLink` in the extension (G9).** A small **2.4d** after 2.4c using the `claims` seam (recommended) **or** under M2.12 or M2.8.
8. **Interception toggle (G11).** Leave it to M2.5 as a local `storage.local` flag the popup flips (recommended; the extension's one local setting) **or** a new `setInterception` message so Kasi owns it.
9. **Host relaunch after the user quits Kasi (G8).** Leave the TRD behaviour, record it as a follow-up for M2.2b/M2.8 to decide (recommended) **or** have the host launch only on the first connection of a browser session.
