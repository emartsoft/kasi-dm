## 1. Scope and decisions

`Kasi.Ipc` is the contract and the transport between the native messaging host (`Kasi.NativeHost`) and the main application, and nothing else. It references no UI assembly and, to stay trivially Native AOT safe, **no other Kasi project** (`Kasi.Core` is not needed for message records).

- **One addition to the TRD protocol (decided).** The options page must open Kasi's settings (TRD 9.1), and TRD 9.4 has no message for it. The protocol gains **`openSettings`** (extension → Kasi, answered with `ack`; Kasi shows its settings window, starting the tray app first if needed). 2.1a updates TRD 9.4 (the table and the count) in the same PR and records the change in ADR 0016; the alternative, a `kasi://` handler registered by the installer, was rejected because the pipe, the launcher and the allow-listing already exist and nothing new would be registered on the machine.
- **Strict by default (`TRD 9.4`, `NFR-010`).** Every message has `v` (protocol version, 1), `id` (correlation id) and `type`. A message with an unknown `type`, an unknown field, a missing required field, a wrong type, or a `v` other than 1 is rejected with a `JsonException`/`IpcProtocolException` before any handler sees it.
- **One schema, three consumers.** `docs/protocol/kasi-messages.schema.json` (JSON Schema **draft-07**, the draft best supported by `json-schema-to-typescript`) is the single source of truth. C# validates against it with shared **sample fixtures**, the extension generates its types from it and validates the same fixtures with Ajv.
- **No C# schema validator.** A package such as JsonSchema.Net would be a new dependency. Instead `tests/fixtures/ipc/valid/*.json` and `tests/fixtures/ipc/invalid/*.json` are read by both test suites: C# must deserialize every valid file, round-trip it to an equal document, and reject every invalid file; the extension's Vitest (M2.3) must validate the valid files and reject the invalid ones with Ajv. A change to either side that the other does not follow fails one of the two suites.
- **Native AOT (`TRD 5.2`).** `Kasi.Ipc` is `IsAotCompatible`; serialization goes through a source-generated `IpcJsonContext`, no reflection.
- **Per-user transport (`TRD 5.1`, `9.3`).** The pipe is `\\.\pipe\kasi-<user SID>` and only that user can open it.

## 2. Design

### 2.1 The messages (`src/Kasi.Ipc/Messages`, 2.1a)

An abstract `IpcMessage` (`v`, `id`) with eleven sealed records, polymorphic on `type` (the ten of TRD 9.4 and `openSettings`, see below):

| Type | Direction | Fields (all required unless marked optional) | Caps |
| --- | --- | --- | --- |
| `hello` | extension → Kasi | `client` (`chrome`, `edge`, `firefox`), `extensionVersion`, `protocolMin`, `protocolMax` | strings ≤ 64 |
| `rules` | Kasi → extension | `enabled`, `extensions[]`, `mimeTypes[]`, `excludedSites[]`, `bypassKey` (`alt`, `ctrl`, `shift`, `none`), `ackTimeoutMs` | each list ≤ 1,000 entries, entry ≤ 256 |
| `addDownload` | extension → Kasi | `url`, `finalUrl`, `referrer` (optional), `filename`, `mime`, `userAgent`, `cookies[]` (`name`, `value`, `domain`, `path`, `secure`, `httpOnly`) | url ≤ 8,192; cookies ≤ 200, value ≤ 4,096 |
| `addBatch` | extension → Kasi | `referrer`, `links[]` (`url`, `filename` optional), `cookies[]`, `userAgent` | links ≤ 100,000, total frame ≤ 64 MiB |
| `mediaDetected` | extension → Kasi | `tabId`, `pageUrl`, `kind` (`hls`, `dash`, `direct`), `url`, `title` (optional) | url ≤ 8,192 |
| `captureMedia` | extension → Kasi | `tabId`, `url`, `kind`, `cookies[]`, `referrer`, `userAgent` | as above |
| `refreshLink` | Kasi → extension | `jobId`, `referrerUrl`, `matchHint` (optional file name or host) | url ≤ 8,192 |
| `linkRefreshed` | extension → Kasi | `jobId`, `url`, `cookies[]` | as above |
| `openSettings` | extension → Kasi | `section` (optional: `general`, `browser`; default `browser`) | strings ≤ 64 |
| `ack` | both | `ok` (always true), `detail` (optional) | detail ≤ 256 |
| `error` | both | `code` (`INVALID_MESSAGE`, `UNSUPPORTED_VERSION`, `APP_NOT_RUNNING`, `APP_NOT_INSTALLED`, `INTERNAL`), `detail` (optional, never a URL with a query) | detail ≤ 256 |

URLs are absolute `http` or `https` (or `ftp`/`ftps` for `addDownload`); the caps keep the 64 MiB frame limit from being a memory risk after parsing. Cookie values are secrets: they are never logged or put in an exception message (CLAUDE.md rule 3).

Serialization settings, each proven by a test and not assumed: `AllowOutOfOrderMetadataProperties = true` (the browser can send `type` last), `UnmappedMemberHandling = Disallow` on the context and on every derived type, `RespectRequiredProperties = true`, a missing, unknown or non-string `type` is a `JsonException`, `v != 1` is `UNSUPPORTED_VERSION`.

### 2.2 The schema (`docs/protocol/kasi-messages.schema.json`, 2.1a)

Draft-07, one `oneOf` over the eleven message definitions discriminated by `type`, `additionalProperties: false` everywhere, string `maxLength` and array `maxItems` from the table above, `format: uri` plus a `pattern` for the allowed schemes. A short `docs/protocol/README.md` states the rules (versioning, caps, who owns the file).

### 2.3 Transport (`src/Kasi.Ipc/Transport`, 2.1b)

- **Framing:** a 4-byte little-endian length, then UTF-8 JSON, the same shape as the browser's native messaging frame; receive cap 64 MiB, a length of 0 or over the cap closes the connection.
- **`KasiPipeNames`:** `kasi-` + the current user's SID.
- **`KasiPipeServer`:** `NamedPipeServerStreamAcl.Create` with unlimited instances, `PipeOptions.Asynchronous | CurrentUserOnly`, and an explicit `PipeSecurity`: allow `ReadWrite | CreateNewInstance` to the current user's SID only (the creator needs the create right to open more instances), and an explicit **deny for the NETWORK SID** so the pipe cannot be reached over SMB. The first instance is created with `FirstPipeInstance`, so a process that grabbed the name first makes startup fail loudly instead of Kasi serving a squatted pipe.
- **Many clients, push to a chosen one.** The server accepts any number of host connections. After `hello`, a connection is registered (client kind, protocol version). `SendAsync(connection, message)` and `BroadcastAsync(message)` push `rules` and `refreshLink`; request/response correlation by `id` covers the calls that expect an `ack`.
- **`KasiPipeClient`:** connects with a timeout, **verifies the server before sending a byte** (the server process's owner SID equals the client's SID), sends and receives framed messages, and surfaces a closed pipe as an event so the host can react.
- **Errors never echo input:** a rejected message produces an `error` reply with a code, not the offending text.

## 3. Verification

- **2.1a:** `IpcMessageSerializationTests` (round trip of all eleven types through `IpcJsonContext`); `StrictValidationTests` (missing `v`, `id` or `type`; unknown `type`; extra field at the top level and inside a nested cookie; wrong value types; `v` of 2; `type` placed last; duplicate properties); the shared fixtures in `tests/fixtures/ipc` (every valid file round-trips equal, every invalid file is rejected); a test that every `JsonDerivedType` has a valid fixture and an invalid one; an architecture test that `Kasi.Ipc` references no Avalonia and no other Kasi project; AOT-compatible build with zero warnings.
- **2.1b:** `PipeRoundTripTests` (hello, rules push, addDownload with ack, many clients, push to one); `PipeLimitTests` (length 0, length over 64 MiB, truncated frame, garbage bytes: the connection closes, the server keeps serving the next one); `PipeSecurityTests` (the DACL read back from a created pipe contains exactly the current user's allow entry and the NETWORK deny, nothing for Everyone or Users; a second server instance of the same name fails because of `FirstPipeInstance`; the client refuses a server owned by another SID, using a test double for the owner lookup); an **elevated-only integration test** that creates a temporary local user, tries to open the pipe as that user and expects access denied (skips without Administrator, `KASI_REQUIRE_VHD`-style switch `KASI_REQUIRE_ADMIN=1` on CI, which is elevated).
- **Mutation checks:** drop the NETWORK deny, widen the allow to Everyone, and accept `v` of 2: each must fail a named test.
- Build, full tests, `dotnet format --verify-no-changes`; two approvals worth of review, recorded as a checklist in the PR (security label).
