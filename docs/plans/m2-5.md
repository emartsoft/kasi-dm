## 2. Design

### 2.1 Status without polling (`KASI-BRW-006`)

The extension shows "disconnected" as soon as it is told, and the popup refreshes itself while it is open.

- **Chromium and Firefox host missing:** the port dies at once; `lastFailure = host-missing` (exists since 2.4b).
- **Kasi not installed or not running:** the host's `error APP_NOT_INSTALLED` or `APP_NOT_RUNNING` marks the port disconnected (exists since 2.4b).
- **Kasi quits while connected (new, decision 3):** the host, on losing the pipe, sends one `error APP_NOT_RUNNING` and **exits** instead of relaunching Kasi at once. The extension therefore turns disconnected at the moment Kasi quits, which is inside 5 s by construction.
- **Reconnecting (new, decision 3):** after a *lost* connection the port manager does not reconnect on a timer. It reconnects when there is a reason: the next matching download (the 2.4b ready phase starts Kasi through the host), the popup being opened, or the browser starting. A user who quits Kasi therefore does not get it back 30 seconds later (plan m2-4 G8).
- **Popup:** while open it asks the background for the state once per second (the popup page is alive, so a timer is safe) and re-renders. The badge (`!`, 2.4b) is set and cleared from the same state.

### 2.2 Interception toggle (decision 4)

A single boolean in `storage.local` (`interceptionEnabled`, default true), flipped from the popup and read by `interception.ts` before the rules (the first thing in `handle`, ahead of `claims`, except that claims such as a refresh watcher still run). It is the extension's one local setting; TRD 9.1 gets one sentence saying so. A badge `off` text shows when it is off.

### 2.3 The link batch (`addBatch`, `KASI-BRW-005`)

Valid shape only (schema `addBatch`): `referrer` (the page URL), `links` (1 to 100,000 of `{ url, filename? }`), `cookies` (read like 2.4b's, for the page and for each distinct link host, 200 cap, values over 4,096 dropped), `userAgent`.

- **Collection** runs in the content script that already exists in every frame (`content/index.ts`). A new message `{ kind: 'kasi-collect', scope: 'all' | 'selection' }` returns the links of that frame; the background merges frames. `scope: 'selection'` takes anchors that intersect the selection range.
- **Filtering before sending:** only http, https and ftp; resolved against `document.baseURI`; at most 8,192 characters; fragment-only and `javascript:` dropped; duplicates removed (first one wins). More than 100,000 links keeps the first 100,000 and says so in the log (never the URLs).
- **`filename` hint** (decision 1): the `download` attribute if present, else the last path segment, as 2.4b does for `addDownload`. No link text crosses the protocol.
- **Size:** browser to host allows 64 MiB; 100,000 links of 8 KiB would exceed it, so the batch is also cut at 32 MiB serialized (the TRD limit has headroom for the cookies).
- **Ack:** the ack for `addBatch` means Kasi has queued the picker (same meaning as `addDownload`, ADR 0019). A timeout shows the disconnected badge; the page is not changed and nothing is retried.

### 2.4 Context menus (`KASI-BRW-004`)

Created once in `runtime.onInstalled` and re-created when the background starts with no menus (a service worker restart does not fire `onInstalled`); ids are fixed strings so a second create is a no-op error that is caught. Titles come from `_locales`.

| Menu | Contexts | Action |
| --- | --- | --- |
| Download with Kasi | `link`, `image`, `video`, `audio` | `addDownload` for `info.linkUrl` / `info.srcUrl`: `url = finalUrl`, `filename` from the URL, `mime = ''` (Kasi resolves both from the response), `referrer = info.pageUrl`, cookies for the URL, user agent. Same eligibility checks as section 2.5 of `m2-4.md` (scheme, length). |
| Download all links | `page` | collect `scope: 'all'`, send `addBatch` |
| Download selected links | `selection` | collect `scope: 'selection'`, send `addBatch` |

A menu click never pauses anything (there is no browser download). If the port is not connected, the click reconnects and waits for `rules` up to the same 6 s ready budget, then shows the disconnected badge. Menus do not depend on the interception toggle: a user who switched interception off still has them.

### 2.5 `refreshLink` (2.5c, TRD 6.6)

`refreshLink {jobId, referrerUrl, matchHint?}` from Kasi opens the referrer page in a background tab, watches `downloads.onCreated` through the existing `claims` seam, and on the first download that matches (by `matchHint` against the file name, else the first one) cancels and erases it, reads cookies for its final URL, and sends `linkRefreshed {jobId, url, cookies}`. The tab is closed afterwards and after 60 s at most. The claim runs before the rules, so the refreshed download is never also handed to Kasi as a new job. No new permission (`tabs` is not needed to create and remove a tab that this extension opened). The Kasi side (the dialog that asks the user, and the send) is M2.8d.

## 3. Verification

- **Unit (Vitest, node environment, no browser, no DOM library):** the pure link collector over a plain `{ anchors: { href, download? }[], baseURI, selection? }` input (100+ relative and absolute links, duplicates, `javascript:`, fragments, over-long URLs, base URI with a path, selection subset, the 100,000 and 32 MiB cuts); `addBatch` and menu `addDownload` validated against the schema and the shared fixtures; menu creation idempotent and one click per item; the toggle (off intercepts nothing, claims still run, menus still work); the port manager (no timer reconnect after a lost connection, reconnect on a download, on the popup, on start; `APP_NOT_RUNNING` unsolicited marks disconnected) with fake timers; the 5 s statement as a fake-timer test that the badge is set in the same tick as the notice; `refreshLink` (match by hint, first match, no match times out at 60 s and sends nothing, claimed download not also intercepted, tab closed in every path).
- **Host (xUnit, `Kasi.NativeHost.Tests`):** on a lost pipe the host writes exactly one `APP_NOT_RUNNING` error and exits with a distinct code, and does not start the launcher (`AppLauncherTests` fake counts launches); the existing reconnect-once-on-send behaviour stays for a send that fails.
- **End to end (Chromium and Firefox, `extension/tests/e2e`, the 2.4c harness):** `TC-BRW-005` extension half: the page with 40 links, the test dispatches the menu handler through `worker.evaluate` (Chromium) or the extension's own test hook message (Firefox; WebDriver cannot click a native menu, see G5), the stub receives one `addBatch` with the 40 URLs, the right `referrer` and a canary cookie; the stub gains an `addBatch` recording like `addDownload`. Status: the stub's pipe is closed (`POST /_stub/stop-pipe`, new) and the popup reads "not connected" within a generous 15 s poll (the 5 s promise itself is the fake-timer unit test), then a download that matches starts Kasi again through the launch chain of 2.4c. The right-click itself stays in `docs/qa/browser-interception.md`.
- **Mutation checks, each must fail a named test:** a timer reconnect after a lost connection; `APP_NOT_RUNNING` ignored when unsolicited; menus created on every worker start; `javascript:` links kept; the 100,000 cap removed; the toggle ignored; a refreshed download also sent as `addDownload`; the host relaunching on a lost pipe.
- `npm run lint`, `format:check`, `check:types`, `npm test`, `npm run build`, `npm run test:e2e` (CI), `dotnet build`, `dotnet test --filter "Category!=Integration"`, `dotnet format --verify-no-changes`.

## 5. Security and privacy

- Links and cookies are sent once to the local host and never stored or logged; the log shows counts only. Cookies are read after the user's menu click, for the hosts in the batch only.
- The content script only answers `kasi-collect` from this extension's own background (`sender.id`); a page cannot trigger a collection or read the answer.
- No new permission and no remote code. `refreshLink` only opens a URL Kasi already holds for a job the user owns, and only from the pipe (never from a page).
- The toggle is local state a page cannot reach.

## 6. Decisions (open: the first option of each is recommended)

1. **Link text across the protocol.** Keep the schema as it is: `filename` carries the `download` attribute or the last path segment, and the picker's text filter matches the URL and that name (**recommended**; no protocol change, no version gating). **Or** add an optional `text` (to 256 characters) to `link`: an older Kasi would reject the whole batch, so it would need a capability flag in `rules` first.
2. **Clipboard capture (`BRW-007`, `TC-BRW-008`).** Build it in Kasi as an app setting, off by default, in M2.8e (**recommended**: no new permission, works with no extension, matches TRD section 2, which says Kasi captures the clipboard even with no extension). **Or** in the extension with `clipboardRead` and an offscreen document (a new permission, a store justification, and it only works while a browser is open).
3. **How the extension learns Kasi quit, and what Quit means.** The host sends `APP_NOT_RUNNING` and exits on a lost pipe, and the extension reconnects only when there is a reason (**recommended**; closes plan m2-4 G8, changes `Kasi.NativeHost` and its tests). **Or** a `ping`/`pong` pair in protocol v1 with a 5 s timer (more traffic, a protocol change, and the relaunch behaviour stays). **Or** leave it: the status can be stale after Kasi quits and `BRW-006` is only met for a missing host.
4. **Interception toggle.** A local `storage.local` flag the popup flips, as m2-4 decision 8 recommended (**recommended**). **Or** a `setInterception` message so Kasi owns it (a protocol and Kasi change).
5. **Where `refreshLink` lives.** 2.5c, here (**recommended**: same plumbing, small). **Or** with M2.12's cookie work.
6. **DOM in unit tests.** Pure collector over a plain input, DOM adapter covered by the Playwright suite (**recommended**; no dependency). **Or** add `jsdom` (MIT) as a dev dependency for adapter-level unit tests.
